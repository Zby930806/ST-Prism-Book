# 双子札记

模型根据最近的剧情，在故事外就后续写法提出问题（使用原版「嘤嘤札记」提示词）。经确认的方案作为「安排」，可选择注入正文，逐步写入故事。

## 使用步骤

1. 打开「札记」页，在页面底部的「独立 API 设置」中填写 API 地址、密钥和模型名（OpenAI 兼容接口），点击「保存」。
   - 可点击「拉取模型列表」从列表中选择。拉取使用表单中当前填写的地址和密钥，无需先保存，也不会自动更换模型。
   - 服务商不提供列表时，手动填写模型名。
   - 本地服务不需要密钥时可留空。不支持 Claude 原生接口。
2. 打开页面顶部的「启用双子札记」开关，正文生成完成后点击「生成札记」。启用流式输出时，生成过程只显示在札记页，不插入正文。
3. 每份札记的 Q1–Q4 下方有「采用方案」，修改为需要的写法后点击「确认安排」，不采用则点击「搁置」。只有确认后才会进入「已确认的安排」。在聊天中回复「Q1：……」只会被下一份札记读取，不会自动确认。
4. 需要正文按安排书写时，在页面底部「自动生成与注入」中启用「注入已确认安排」。待兑现和进行中的安排注入正文；标为已完成或已取消后停止注入。安排是写作方向，不是已发生的事件。

札记只使用此处填写的 API，不使用正文或摘要的 API。

## 自动生成

在「自动生成与注入」中可启用「自动生成札记」：每次正文生成完成后自动生成一份。安静生成、代写（扮演）、试运行和切换聊天不触发；失败不自动重试。

使用过原版札记时，需关闭悬浮球中的札记自动生成，以及预设中要求正文输出 aftertalk 的条目，以免每轮生成两份。插件不修改预设。

## 札记读取的内容

最近几层正文和用户原话、已有的摘要和总结（包括 L1/L2）、当前的人物和物品等状态、上一份札记，以及已确认或搁置的安排。总量受「摘要和状态最多读多少字」限制。

札记不修改摘要、计划、角色或物品。摘要会跳过正文中的 aftertalk，不将戏外讨论作为剧情；已生成的摘要不会被自动清理。

## 导入正文里的 aftertalk

页面底部的「导入正文里的札记」将正文中已有的 aftertalk 导入为札记。重复导入不会产生重复记录；不修改正文；其中标为「已确认」的内容不会自动成为安排。

## 札记的失效条件

每份札记与对应楼层的正文绑定。该楼被改写、重抽或删除后，札记标为「已失效」，只能查看，不能再确认其中的方案。对同一段正文重新生成札记时，旧札记中未确认的方案失效，已确认的安排不受影响。

## 截断与报错

- 「最大输出」默认 8000，最大可设为 65535。已保存的设置若仍为旧默认值 3000，会自动按 8000 使用；手动修改过的数值保持不变。
- 札记生成中途达到最大输出时，保存已生成的部分，末尾标明「被截断」，页面提示内容不完整并显示当前的最大输出。经常被截断时，调大「独立 API 设置」中的「最大输出」；思考型模型的思考过程也计入其中。
- 最大输出超过模型自身上限时，服务商会拒绝请求，提示「最大输出超过了这个模型的上限」，按提示调小即可。
- 其他错误（密钥、额度、地址、网络等）会说明原因和修改位置，已有札记不受影响。服务商原文显示在「技术细节」中，密钥会被遮盖。
- 更多见 [常见报错](常见报错.md)。

## 数据存储

- 设置：酒馆扩展设置中的 prism_book_notes_settings。API 密钥也存于此处，分享设置备份前需删除。
- 札记和安排：各聊天元数据中的 prism_book_notes。
- 无法识别数据格式时只读保护，不覆盖；保存失败时保留原有数据。
- 札记每页显示 5 份，安排每页 10 条；模型返回的内容仅以纯文本显示。

## 提示词来源

提示词完整取自用户提供的「十四行诗 v3.0」中的「📖丨嘤嘤札记@泉此方」，原文和署名保存在 src/notes/prompt.ts，可在札记页底部的「原版提示词」中只读查看。运行时只展开原有的 setvar 宏、去除注释和 trim 宏，规则本身未修改；另附一段说明，内容仅限独立面板和数据存放的边界。

原文中有「感谢泉佬授权」的注释，但本项目未核实其是否允许公开再分发。维护者分发时，应确认现有授权覆盖该提示词，并保留原署名。
