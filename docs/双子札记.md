# 双子札记

模型读完最近的剧情，在故事外提几个问题和你商量后面怎么写（用的是原版「嘤嘤札记」提示词）。你确认过的方案才算「安排」，可以选择交给正文模型慢慢写进故事。

## 开始用

1. 打开「札记」页，在页面底部的「独立 API 设置」里填写 API 地址、密钥和模型名（OpenAI 兼容接口），点「保存」。
   - 可以点「拉取模型列表」从列表里选。拉取用的是表单里刚填的地址和密钥，不用先保存，也不会自动替你换模型。
   - 服务商不提供列表时，直接手动填写模型名。
   - 本地服务不需要密钥时可以留空。不支持 Claude 原生接口。
2. 打开页面顶部的「启用双子札记」，等正文生成完，点「生成札记」。开着流式输出时，生成过程只显示在札记页，不会插进正文。
3. 每份札记里的 Q1–Q4 下面有「采用方案」，改成你想要的写法后点「确认安排」，不想要就点「搁置」。只有点了确认，才会进入「已确认的安排」。在聊天里回复「Q1：……」只会让下一份札记读到，不会自动确认。
4. 想让正文模型照着写，在页面底部「自动生成与注入」里打开「注入已确认安排」。待兑现和进行中的安排会交给正文模型；标成已完成或已取消后就不再交。安排是写作方向，不是已经发生的事。

札记只用这里填的 API，不会借用正文或摘要的 API。

## 自动生成

在「自动生成与注入」里可以打开「自动生成札记」：每次正文写完后自动生成一份。安静生成、代写（扮演）、试运行和切换聊天不会触发；失败不会自动重试。

以前用过原版札记的话，先关掉悬浮球里的札记自动生成，以及预设里让正文输出 aftertalk 的那一条，免得一轮出两份。插件不会改你的预设。

## 札记会读到什么

最近几层正文和你的原话、已有的摘要和总结（包括 L1/L2）、当前的人物物品等状态、上一份札记，以及你确认或搁置过的安排。总量受「摘要和状态最多读多少字」限制。

札记不会改动摘要、计划、角色或物品。摘要会跳过正文里的 aftertalk，不把戏外讨论当成剧情；以前已经生成的摘要不会被自动清理。

## 导入正文里的 aftertalk

页面底部的「导入正文里的札记」会把正文里已有的 aftertalk 读成札记。重复导入不会出现两份；正文不会被修改；里面写着「已确认」的内容也不会自动变成安排。

## 札记什么时候失效

每份札记都和它对应的那一楼正文绑定。那一楼被改写、重抽或删除后，札记会标成「已失效」，只能查看，不能再确认里面的方案。对同一段正文重新生成札记时，旧札记里没确认的方案会失效，已经确认的安排不受影响。

## 被截断或出错时

- 「最大输出」默认 8000，最多可以设到 65535。以前保存的设置如果还是旧默认值 3000，会自动按 8000 用；自己改过的保持不变。
- 札记写到一半就达到最大输出时，已写出的部分会保存，末尾标明「被截断」，页面也会提示内容不完整，并写出当前的最大输出。总被截断的话，调大「独立 API 设置」里的「最大输出」；思考型模型的思考过程也算在里面。
- 最大输出设得比模型自己的上限还大时，服务商会拒绝请求，提示「最大输出超过了这个模型的上限」，按提示调小即可。
- 其他错误（密钥、额度、地址、网络等）会说明原因和去哪里改，已有的札记不受影响。服务商的原话在「技术细节」里，密钥会被遮住。
- 更多见 [常见报错](常见报错.md)。

## 数据存在哪

- 设置：酒馆扩展设置里的 prism_book_notes_settings。API 密钥也存在这里，分享设置备份前记得删掉。
- 札记和安排：每个聊天元数据里的 prism_book_notes。
- 数据格式认不出来时只读保护，不会覆盖；保存失败时保留原来的数据。
- 札记每页显示 5 份，安排每页 10 条；模型返回的内容只按纯文本显示。
