# 双子札记

模型根据最近的剧情，在故事外就后续写法提出问题（使用以「嘤嘤札记」原文为底本的整理版提示词）。经确认的方案作为「安排」，可选择注入正文，逐步写入故事。

## 使用步骤

1. 打开「札记」页，在页面底部的「独立 API 设置」中填写 API 地址、密钥和模型名（OpenAI 兼容接口），点击「保存」。
   - 可点击「拉取模型列表」从列表中选择。拉取使用表单中当前填写的地址和密钥，无需先保存，也不会自动更换模型。
   - 服务商不提供列表时，手动填写模型名。
   - 本地服务不需要密钥时可留空。不支持 Claude 原生接口。
2. 打开页面顶部的「启用双子札记」开关，正文生成完成后点击「生成札记」。也可在聊天中最新一条回复下方的札记卡片里点击「生成札记」（见下方「在聊天中显示札记」）。启用流式输出时，生成过程显示在札记页和札记卡片中，不插入正文。
3. 每份札记的 Q1–Q4 下方有「采用方案」，修改为需要的写法后点击「确认安排」，不采用则点击「搁置」。只有确认后才会进入「已确认的安排」。在聊天中回复「Q1：……」只会被下一份札记读取，不会自动确认。
4. 需要正文按安排书写时，在页面底部「自动生成与注入」中启用「注入已确认安排」。待兑现和进行中的安排注入正文；标为已完成或已取消后停止注入。安排是写作方向，不是已发生的事件。「已确认的安排」标题旁显示实际注入的条数（「注入中 · N 条」）。

札记只使用此处填写的 API，不使用正文或摘要的 API。

## 问题的识别

札记中的问题按 Q1–Q4 编号识别，先找「想问用户」小节，只在这一节里识别（进度清单里引用的 Q 编号不算问题）；没有这一节时用全文。行首为 Q1–Q4、后接「.」「、」「:」「）」等标点的写法照常识别；Markdown 标题（### Q1.）、【Q1】、序号开头（1. Q1：）、全角编号（Ｑ１．）、编号后只有空格（Q1 关于……）等写法，需要正文里有「暂定」标记才算问题，免得把正文中偶然出现的「Q1」当成问题。识别不出问题的札记只能查看原文，没有可确认的方案。

## 注入的上限

「设置 → 注入设置」的「记忆注入预算」为 0（默认）时，待兑现和进行中的安排全部注入。填写了预算时，注入的安排清单最多 16000 字：进行中的排在前面，待兑现的按确认时间从新到旧，放不下的这一轮不注入；「已确认的安排」中显示有几条没有注入。把写完的安排标为「已完成」，或把预算改为 0，可以让其余安排注入。

## 在聊天中显示札记

启用双子札记后，聊天中显示札记卡片，外观与楼层面板相同，不需要启用楼层面板：

- 最新一条回复下方：没有札记时可点击「生成札记」，已有札记时可「重新生成」；生成中显示已写出的内容，可取消。API 未填写完整或正文正在生成时，卡片中说明原因。
- 有札记的楼层下方：卡片头显示问题数和已确认数，展开后查看札记全文，逐题修改「采用方案」后确认安排或搁置，与札记页的操作相同。
- 卡片中的「札记页」打开札记页，可整理已确认的安排、查看历史札记。
- 卡片页脚的「删除札记」在原位确认后删除这份札记，见下方「删除札记」。
- 所在楼层被改写、重抽或删除导致失效的札记不在聊天中显示，仍可在札记页查看。

在「自动生成与注入」中关闭「在聊天中显示札记」后不再显示卡片，札记和安排不受影响。

## 自动生成

在「自动生成与注入」中可启用「自动生成札记」：每次正文生成完成后自动生成一份。安静生成、代写（扮演）、试运行和切换聊天不触发；失败不自动重试。

模型回复「本轮无需新增札记」时不保存札记，只在状态中说明；需要时可再次生成。这样的回复不会挤掉上一份札记里的进度清单和待确认的提案。以前保存下来的这类记录（既没有问题也没有进度清单）不再作为下一次请求里的「上一份札记」。

使用过原版札记时，需关闭悬浮球中的札记自动生成，以及预设中要求正文输出 aftertalk 的条目，以免每轮生成两份。插件不修改预设。

## 札记读取的内容

每次生成札记发送以下内容，各部分有各自的上限（按字符计）：

- 最近几层正文和用户原话：层数按「参考最近几层」（1–40，默认 8）。正文合计至少 24000 字，参考层数多于 8 层时每层加 3000 字（40 层时为 120000 字），每层最多 6000 字；从最新往前放，放不下的较早楼层不发，并注明省略了几层。
- 已有的摘要和总结（包括逐楼摘要），按时间顺序，从实际放进正文的最早一层之前选取，被挤掉的楼层由摘要覆盖。
- 当前状态，写成紧凑文字（不带内部编号和时间戳），按重要程度排列：未了结的计划与悬念、时间地点与局势、主角、主要角色与在场或同区域的角色、物品、近期已了结的计划与悬念、其余角色（只列名字、身份和所在地）。
- 摘要和状态合计按「摘要和状态最多读多少字」（默认 12000，可填 1000–40000；填 0 不限制）：状态最多占其中 35%，按上面的顺序放入，放不下的整条省略并注明，不在中间截断；其余字数给摘要，从最新往前连续保留，并注明更早的省略了几条。
- 角色卡描述，最多 3000 字。
- 上一份札记（有编号问题或进度清单的最近一份），最多 12000 字。
- 用户在面板操作过的安排，逐行写状态、来自哪一楼札记的哪一问和安排正文（不发内部编号和时间戳）：待兑现、进行中的全部列出，已完成、已取消、已搁置的只列最近 30 条；最多 16000 字，从最新往前放，放不下就停并注明。依据的正文已改动的安排会标出来。
- 当前仍要落实的安排（待兑现、进行中），最多 12000 字，同样从最新往前放。

札记不修改摘要、计划、角色或物品。摘要会跳过正文中的 aftertalk，不将戏外讨论作为剧情；已生成的摘要不会被自动清理。

## 导入正文里的 aftertalk

页面底部的「导入正文里的札记」将正文中已有的 aftertalk 导入为札记。重复导入不会产生重复记录；不修改正文；其中标为「已确认」的内容不会自动成为安排。

## 札记的失效条件

每份札记与所在楼层的正文绑定，只核对这一楼本身（页码和正文）：所在楼层被改写、重抽（翻页）或删除后，札记标为「已失效」，只能查看，不能再确认其中的方案。更早楼层的改写、说话方改名和隐藏楼层都不算改动；删除更早的楼层会让楼层号错位，札记随之失效。旧版本保存的札记没有记下所在楼层的指纹，仍按从第 0 楼到札记所在楼的整段正文判断。对同一段正文重新生成札记时，旧札记中未确认的方案失效。

已确认的安排不随札记失效：札记所在楼层被改写、重抽或删除后，安排照常注入，「已确认的安排」中标出「依据的正文已改动」，并提示「取消这条安排」；也可以停用后重新设为待兑现或进行中。重抽后放弃的那条分支上确认的安排同样会继续注入，不再适用时请取消。

## 删除札记

札记页中每份札记展开后，底部有「删除札记」，弹窗确认；聊天中的札记卡片在页脚删除，在原位确认。删除后无法恢复：由这份札记确认的安排一起删除，其中待兑现和进行中的安排随之停止注入；其他札记和安排不受影响。生成札记时不能删除。

## 截断与报错

- 「最大输出」默认 8000，最大可设为 65535。已保存的设置若仍为旧默认值 3000，会自动按 8000 使用；手动修改过的数值保持不变。
- 札记生成中途达到最大输出时，保存已生成的部分，末尾标明「被截断」，页面提示内容不完整并显示当前的最大输出。经常被截断时，调大「独立 API 设置」中的「最大输出」；思考型模型的思考过程也计入其中。
- 最大输出超过模型自身上限时，服务商会拒绝请求，提示「最大输出超过了这个模型的上限」，按提示调小即可。
- 其他错误（密钥、额度、地址、网络等）会说明原因和修改位置，已有札记不受影响。服务商原文显示在「技术细节」中，密钥会被遮盖。
- 更多见 [常见报错](常见报错.md)。

## 数据存储

- 设置：酒馆扩展设置中的 prism_book_notes_settings。密钥保存在酒馆的扩展设置（settings.json）中，分享 settings.json 或截图前需删除或遮盖；用「设置备份」导出的文件已去掉密钥。
- 札记和安排：各聊天元数据中的 prism_book_notes。
- 无法识别数据格式时只读保护，不覆盖；保存失败时保留原有数据。
- 札记每页显示 5 份，安排每页 10 条；模型返回的内容仅以纯文本显示。

## 提示词来源

提示词取自用户提供的「十四行诗 v3.0」中的「📖丨嘤嘤札记@泉此方」。原文和署名完整保存在 src/notes/prompt.ts 的 ORIGINAL_NOTES_PROMPT，可在札记页底部的「原版提示词」中只读查看。

自 1.2.9-prism.18 起，运行时使用同一文件中的整理版（TIDY_NOTES_PROMPT，札记页底部「整理版提示词」可查看）。整理版以原文为底本：合并重复的条目，统一问题的话题清单，把插件中不存在的「节奏挡位」改为「当前剧情节奏」；凝嘤嘤的口吻、定义到格式的各节、Q1–Q4 编号问题、「凝嘤嘤暂定」和「收尾」的格式与原文相同，aftertalk 的输出格式逐字一致。整理版沿用原文的宏写法，运行时同样只展开 setvar 宏、去除注释和 trim 宏；另附一段说明，内容仅限独立面板和数据存放的边界。
