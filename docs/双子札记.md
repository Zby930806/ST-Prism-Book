# 双子札记

## 入口与首次配置

在棱镜宝书底部选择「札记」。默认未启用，不会自动发送请求。

1. 展开「独立 API」，填写自己的 **OpenAI 兼容**地址和密钥，点击「拉取模型列表」，搜索并下拉选择模型，再保存。拉取使用当前表单中的地址和密钥，不要求先保存或预填模型，不调用生成接口；不会自动改选模型。服务商不提供模型列表时仍可手动填写模型 ID。密钥允许为空，方便无鉴权的本地服务；不支持 Claude 原生 Messages 协议，也不借用正文或摘要渠道。
2. 打开启用开关，等正文生成结束后点击「生成札记」。开启流式后，过程只在面板展示，不插回正文。
3. 对具体 Q 问题编辑「采用方案」并确认。只有这种明确操作才加入正式安排。最近用户消息中的 Q 编号答复仍会供札记阅读、核对，但不会自动把不明确的原话变成决定。
4. 需要正文采纳时，开启「注入已确认安排」。清单属于戏外写作安排，不是剧情事实；完成、取消或因正文修改而失效的条目不再注入。完成状态由用户管理，不能让札记模型自行宣称兑现。

自动生成是可选开关：正文完成并渲染后才触发；不响应 quiet、扮演、干跑或单纯切换聊天，不在失败时自动重试。启用前请关闭原悬浮球的札记自动生成；如果正文预设仍要求直接输出 aftertalk，也请关闭原正文触发，避免双份札记。插件不会修改你的预设文件。

## 与现有宝书的关系

- 最近正文和用户原话、已有有效摘要压缩层（包含 L1/L2）、当前人物物品等状态、上一份札记以及用户确认/拒绝记录只读提供给独立 API，受上下文字数预算控制。
- 不清空或重建以前的1800楼摘要；不把札记提案写进剧情计划、NPC、物品或摘要。已有旧版数据若被宝书判定需要转换或只读保护，札记不会绕过保护读取或改写它。
- 旧消息中的 aftertalk 可通过显式导入放进札记历史。重复导入去重；原消息不改动，其中自称「已确认」的内容也不会自动变成正式安排。
- 默认摘要输入过滤 aftertalk，包括未闭合的尾部札记块，避免把戏外讨论当正文。但这不会自动清理已经生成过的受污染旧摘要。
- 札记历史分页显示，每页5份；安排清单每页10项；纯文本显示，不执行模型返回的 HTML。

## 数据与保护

设置独立保存于酒馆 extensionSettings.prism_book_notes_settings；聊天数据保存于 chatMetadata.prism_book_notes。API 密钥跟随酒馆扩展设置保存，**分享设置备份前务必移除密钥**。

模型列表只在当前页面临时保存。更换地址或密钥会清空列表并取消旧请求；迟到的返回不会覆盖新列表。列表最多显示 200 个匹配项，可搜索缩小范围；拉取失败不会清空当前已填写模型，可取消或重试。

切换聊天、改写/重抽正文、取消请求后不采用迟到的生成结果。正文来源变动会让旧方案失效；旧札记仍可查看。重新生成同一段正文仅淘汰旧札记的待选问题，不抹掉用户已经确认且正文来源仍有效的安排。

未知数据版本只读保护；保存失败保留原数据。接口失败保留前一份札记，不退回正文 API，不无限重试。配置保存使用酒馆自带防抖保存接口；网络断开时应恢复连接后再次保存。
