# 创作规划（大纲）

位置：**摘要 → 当前局势与计划 → 创作规划**。根据剧情和你的想法，让模型写一份分阶段的规划；确认后，一次只把当前阶段交给正文模型。

## 用法

1. 展开「生成规划草稿」，写下你希望故事怎么发展：人物关系往哪走、想要的转折、节奏、不想出现的情节。选好分几个阶段（1–12），点「生成规划草稿」。
2. 模型会参考最近的剧情、你的原话、已有的摘要和总结（包括 L1/L2）、人物和物品等状态，写出草稿。
3. 在草稿里修改规划标题、整体发展方向、整体约束，以及每个阶段的目标、剧情要点、发展方式和推进条件，然后点「保存草稿」。
4. 点「确认加入计划」。确认之前不会影响正文；重新生成的草稿也不会替换正在用的规划。
5. 照常聊天。正文模型会收到整体约束和当前阶段。阶段由你手动切换（「下一阶段」「结束规划」），也可以随时暂停。

规划是写作方向，不是已经发生的事。切换阶段只代表规划的进度，摘要仍然只记录正文里真正发生的事。模型不保证每一轮都照着写；你最新的要求和已有的剧情优先，模型也不会替你的角色做决定。剧情明显偏离时，可以按新的想法重新生成，核对后替换。

## 和模型讨论

「和模型讨论规划」可以先聊聊人物动机、节奏或走向：选参考哪个版本（正在用的规划、草稿，或者不参考），写下你想聊的，点「发送」。可以多轮，讨论记录按聊天保存，刷新后还在。

讨论不会改动规划，也不会交给正文。想采纳时点「按讨论生成草稿」，会再请求一次 API 生成新草稿；正在用的规划不受影响，新草稿也要你确认后才生效。

讨论只参考已经保存的版本，编辑器里没保存的修改不会发出去。每次提问最多 4000 字，回答最多 8000 字，最多保留 12 轮、共 48000 字，超出时会提示，不会悄悄删掉旧记录。请求只带上最近约 24000 字的问答，较早的意见模型可能读不到，重要的要求请在最新一轮再说一次。「清空讨论」只清空讨论记录，草稿、规划、札记和摘要都不受影响。

## 用哪个 API

默认用札记填好的 API（不需要打开札记功能），也可以在「规划 API 设置」里给规划单独设一个，同样能拉取模型列表。不会改用正文或摘要的 API。只有你点按钮时才会请求，失败也不会自动重试。

## 长度

- 每份规划 1–12 个阶段，每个阶段 1–8 个剧情要点。
- 整份规划最多 48000 字符（包括 JSON 的标点和空白），模型的原始回复最多 100000 字符。标题 240 字，整体发展方向 4000 字，每条约束 1200 字；每个阶段的目标 2400 字、发展方式 3200 字、每条要点 1600 字、推进条件 2000 字。这些都是字符数，不是 token 数，也不是建议写满的篇幅。
- 交给正文的部分（整体约束、当前阶段和固定说明）最多 16000 字符；超出时草稿照样能保存，但要精简之后才能启用。

规划内容的长度上限和 API 的「最大输出」是两回事。回复被截断时，页面会说明是输出达到了上限，并写出当前的最大输出：用札记的 API 时到「札记 → 独立 API 设置」调大，用专用 API 时在「规划 API 设置」里调大；也可以少分几个阶段。被截断的回复不会存成草稿。

## 格式出错时

模型的回复和你保存的编辑用同一套检查。出错时会指出具体的字段，例如 `chapters[1].approach` 指第 2 阶段的「发展方式」，并说明是缺失、类型不对、太长还是数量不对。可以接受单个 json 代码块；多出来的字段、写到一半的 JSON、夹杂其他文字的回复都会被拒绝。出错不会替换已有的草稿和规划，也不会自动重试。

## 角色的反应

生成规划和引导正文时都会强调：角色按自己的性格、动机、顾虑和知道的事情行动，情绪和关系接着前文走。允许犹豫、拒绝、误解和一时没有结果的互动，不会为了推进剧情节点突然配合、坦白、和解或翻脸。也不靠口癖、小动作、争吵或长篇心理描写来装「活人感」。剧情节点可以为人物合理的反应让路：推迟、调整或者不实现。

## 保护

- 草稿和正在用的规划分开保存。
- 取消、切换聊天，或者生成期间改了正文或草稿时，迟到的结果不会覆盖现在的内容。
- 正常往后聊不影响规划；改写、重抽、删除它参考过的正文后，规划会暂停生效，需要你核对后点「核对后重新启用」。
- 保存失败保留原来的数据；数据版本认不出来时只读保护。
- 数据存在聊天元数据的 prism_book_outline（规划）和 prism_book_outline_discussion（讨论）里；规划专用 API 的设置在扩展设置的 prism_book_outline_settings，分享设置备份前记得删掉密钥。
