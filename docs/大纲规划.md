# 创作规划（大纲）

位置：摘要 → 创作规划。模型根据剧情和用户要求生成分阶段规划，也可不填要求一键生成；确认后，每次只将当前阶段注入正文。

## 用法

1. 展开「生成规划草稿」，填写期望的故事走向：人物关系的发展、需要的转折、节奏、不希望出现的情节。选择阶段数（1–12），点击「生成规划草稿」。不想填写时可用「一键生成」，见下节。
2. 模型参考最近的剧情、用户原话、已有的逐楼摘要和总结、人物和物品等状态、角色卡、当前启用的世界书条目和双子札记中已确认的安排生成草稿，详见「生成时参考的资料」。
3. 在草稿中修改规划标题、整体发展方向、整体约束，以及各阶段的目标、剧情要点、发展方式和推进条件，然后点击「保存草稿」。
4. 点击「确认加入计划」。确认前不影响正文；重新生成的草稿也不会替换正在使用的规划。
5. 正常聊天。整体约束和当前阶段注入正文。规划卡片中的「推进节奏」决定每轮回复推进多少剧情要点：慢（每轮最多一个，也可以不推进，先把当前场景写充分）、适中（默认，每轮最多一到两个，不在一轮写完所有要点）、快（可以一轮推进多个，但不在一轮写完整个阶段）；慢和适中要求回复停在需要用户回应的地方，修改后从下一次生成起生效。阶段可手动切换（「下一阶段」「结束规划」），也可在推进条件检查中开启自动切换；可随时暂停。规划确认后，推进条件仍可修改：点当前阶段或「全部阶段」中推进条件旁的编辑键，在弹窗中修改并保存。只改推进条件，阶段进度和其他内容不变；当前阶段已有的检查结果随之作废。

规划是写作方向，不是已发生的事件。切换阶段只表示规划进度，摘要仍只记录正文中实际发生的事。模型不保证每轮都按规划书写；用户最新的要求和已有剧情优先，模型也不会替用户的角色做决定。与札记已确认的安排冲突时，正文暂缓冲突的部分，以用户本轮明确的要求和已发生的事实为准，不在正文中向用户提问。剧情明显偏离时，可按新的要求重新生成，核对后替换。

## 一键生成

不填写要求、不指定阶段数，由模型根据角色卡、世界书、宝书记忆和最近剧情自行规划后续 3～6 个阶段：延续未了结的计划和悬念，运用世界书中已有的设定、势力和人物关系，节奏由近及远。

- 没有规划和草稿时，「创作规划」中显示「一键生成规划」卡片，点击「一键生成」即可；生成期间可在卡片中取消，并查看正在生成的内容。
- 已有规划或草稿时，在「修改或重新生成规划」中点击阶段数旁的「一键生成」，确认后生成。一键生成不使用上方填写的要求和阶段数；成功后替换当前草稿（包括未保存的修改），正在使用的规划不受影响。
- 结果同样先存为草稿，「当时的要求」一栏注明来自一键生成。生成完成后自动展开草稿编辑器，核对、修改并确认加入计划后才生效。
- 模型给出的阶段数在 1–12 之间均可接受。填写要求时指定的阶段数与模型给出的不一致时，照常存为草稿，草稿上方提示「要求 N 个阶段，实际 M 个」。

## 生成时参考的资料

填写要求的生成、一键生成和规划讨论使用同样的资料：

- 最近 8 条楼层的正文和用户原话（不含插件的提示楼、番外楼和酒馆原生的系统楼；被宝书隐藏的旧楼照常计入），共约 24000 字，每层最多 6000 字。放不下的较早楼层由摘要覆盖。
- 已有的逐楼摘要（L0）和总结（L1 及以上），按时间顺序排列，从实际放进最近正文的最早一层之前选取。
- 当前状态，写成紧凑文字（不带内部编号和时间戳），按重要程度排列：未了结的计划与悬念、时间地点与局势、主角、主要角色与在场或同区域的角色、物品、近期已了结的计划与悬念、其余角色（只列名字、身份和所在地），以及已知地点、生活档案和自定义变量。
- 摘要、总结和状态在「设置 → 注入设置」的「记忆注入预算」为 0（默认）时不限字数；填写了预算时，摘要和总结最多约 7800 字，从最新往前连续保留，遇到第一条放不下就停，并注明省略了几条；状态最多约 4200 字，按上面的顺序放入，放不下的整条省略并注明。记忆处于只读保护时都不读取。
- 角色卡的描述，以及有内容时的性格和情景，最多 12000 字。
- 当前启用的世界书条目：常驻条目，以及被上述最近楼层触发的条目。读取方式与摘要读取世界书相同，遵守「排除世界书内容」设置，最多 20000 字。读取失败时照常生成，只是不带世界书资料。
- 双子札记中已确认、尚在进行的安排，作为写作方向参考（札记功能关闭时不带）。记忆注入预算为 0 时全部带上；填写了预算时最多约 1500 字，保留最新的，并注明较早的省略了几条。
- 填写的要求；一键生成时为固定的说明。

读取世界书在发送请求之前进行，期间可以取消；读取期间聊天、正文或规划有变化时不发送请求。角色卡和世界书的上限较宽，规划 API 的上下文窗口较小时可能超出，服务商报「上下文超长」时请换用上下文更大的模型。

## 推进条件检查

规划卡片中的「检查推进条件」会把当前阶段（目标、剧情要点、推进条件）和本阶段的正文与用户原话发给规划 API，判断推进条件是否已在正文中满足。计划、约定、预告和猜测不算满足；条件含多项时需全部满足，依据不足时判为未满足。

- 发送的正文：本阶段上次检查以来（没有检查过时从本阶段开始）的消息，至少最近 max(6, 自动检查间隔×2) 条。原文合计最多约 20000 字、每条最多 3000 字，从新到旧放入；放不下的较早楼层改用逐楼摘要（最多约 6000 字），提示词注明摘要只作辅助证据。检查起点只记在当前页面，刷新页面后从最近的 max(6, 间隔×2) 条开始。
- 判断满足时，卡片中显示依据和「切换到下一阶段」「忽略」；未满足时显示还缺什么。手动检查的结果只作提示。
- 勾选「每 N 个 AI 楼自动检查」后，每当 AI 回复数增加 N 条检查一次（默认关闭，N 默认为 3）；判断满足时在酒馆中弹出一次提示。自动检查请求失败，或因规划 API 没有填好而没有运行时，规划卡片中留一条说明，下次检查成功后清除；不影响正文。
- 勾选「满足时自动切换阶段」后（默认关闭，会一并打开自动检查），自动检查判断满足时规划切换到下一阶段，卡片中显示切换所在楼层和依据，可点「退回第 N 阶段」撤回。最后一个阶段不自动结束，只提示手动结束；切换失败时改为提示。
- 每次检查请求一次规划 API。切换阶段、切换聊天或检查期间规划有变动时，迟到的结果会被丢弃；结果不保存，刷新页面后需重新检查。

## 规划讨论

「规划讨论」卡片显示讨论轮数和最近一条回复，点击「开始讨论」或「继续讨论」打开对话界面（手机上为从底部升起的面板，顶部留出状态栏，可下拉关闭；电脑上为居中窗口，可放大）。用于讨论人物动机、节奏或走向，记录按聊天保存，刷新后保留。

讨论由内置的对话角色 Qiheng 回答：说话口语化、短句连发，先下判断再补充，会反问求证、吐槽，也会热烈地夸人；粗口和方言随场景，对说话客气的人和严肃的话题会收敛，不给用户起昵称。打招呼、道谢、被夸或说累时只回一两句，不顺势展开规划，也不编自己的日常和经历。说话方式按一位朋友的聊天习惯提炼（本人同意公开），只含说话方式，不含聊天原文、称呼和现实经历。讨论界面只能发文字，不发表情包。

也可以在讨论窗口右上角「更多操作 → 讨论角色」换成自定义角色：填写名字和人设提示词（最多 4000 字），可以上传头像，不传时显示名字的第一个字。自定义的人设只替换说话方式，只讨论后续方向、不替用户拍板、不声称已经保存、只依据资料等规则照常附上，与人设冲突时以规则为准。设置随规划设置保存，选回 Qiheng 即恢复。

- 顶部「参考」选择讨论参考的版本：正在使用的规划、草稿或不参考。
- 在底部输入框填写问题，点击发送按钮或按 Ctrl+Enter 发送。发送前先读取世界书，再请求规划 API；等待回复时可点击停止按钮取消；请求失败时问题放回输入框。
- 讨论与生成规划使用同样的资料（见上节），包括世界书条目和札记中已确认的安排。
- 消息旁显示发送和收到回复的时间。Qiheng 的回复左边带头像，按空行拆成几个气泡；标题、列表和粗体按格式显示，每条回复下方可复制。右上角「更多操作」中可复制全部讨论（附时间）、删除最早的一轮或清空讨论。

讨论不修改规划，也不注入正文。需要采纳时点击「生成草稿」，在弹出的面板中选择参考版本和阶段数量（1–12），确认后请求规划 API 按讨论生成新草稿（附加说明讨论里的口语和粗话不带进规划），替换当前草稿（包括未保存的修改）；正在使用的规划不受影响，新草稿同样需确认后生效。生成完成后可点击「查看草稿」跳到草稿编辑器。规划 API 不可用时，对话界面中显示原因和「打开规划 API 设置」。

讨论只参考已保存的版本，编辑器中未保存的修改不会发送。每次提问最多 4000 字，回答最多 8000 字（完整的回答超过 8000 字时截到 8000 字保存，末尾注明已截断），最多保留 12 轮、共 48000 字。发送前为回答预留 8000 字：已有字数加上问题再加 8000 字超过 48000 字时先提示，不发送请求；满 12 轮或接近字数上限时，可删除最早的一轮或清空讨论，不会自动删除旧记录。请求只附带最近约 24000 字的问答，模型可能读取不到较早的意见，重要的要求需在最新一轮重复说明。「删除最早的一轮」「清空讨论」只改讨论记录，不影响草稿、规划、札记和摘要。

## 使用的 API

默认使用札记中填写的 API（无需启用札记功能），也可在「规划 API 设置」中为规划单独设置，同样支持拉取模型列表。不使用正文或摘要的 API。规划专用 API 的「最大输出」默认 8000（思考型模型的思考过程也计入其中）；以前按旧默认 6000 保存、没有改过的设置会自动改为 8000，改过的数值保持不变。生成、讨论和手动检查推进条件只在点击按钮时发送请求，开启自动检查后按间隔发送；失败不自动重试。

报错中写明修改位置：使用札记的 API 时为「札记 → 独立 API 设置」；使用专用 API 时为「摘要 → 创作规划 → 修改或重新生成规划（没有已确认规划时为「生成规划草稿」）→ 规划 API 设置」。

## 长度

- 每份规划 1–12 个阶段，每个阶段 1–8 个剧情要点。
- 整份规划最多 48000 字符（包括 JSON 的标点和空白），模型的原始回复最多 100000 字符。标题 240 字，整体发展方向 4000 字，每条约束 1200 字；每个阶段的目标 2400 字、发展方式 3200 字、每条要点 1600 字、推进条件 2000 字。以上均为字符数上限，不是 token 数，也无需写满。
- 注入正文的部分（整体约束、当前阶段和固定说明）每个阶段最多 16000 字符。草稿编辑器中，超出上限的阶段在阶段列表中标「超出注入上限」，下方说明多出的字数；草稿仍可保存。「确认加入计划」时逐个阶段检查，有阶段超出时不加入，并指出第几阶段多出多少字。

规划内容的长度上限与 API 的「最大输出」是两个独立的限制。回复被截断时，页面会说明输出达到上限，并显示当前的最大输出：使用札记的 API 时在「札记 → 独立 API 设置」中调大，使用专用 API 时在「规划 API 设置」中调大；也可减少阶段数。被截断的回复不保存为草稿。

## 格式错误

模型的回复按与世界书建议相同的方式提取：去掉已闭合的思考块，跳过 JSON 前后的说明文字和代码围栏，取第一个完整的大纲 JSON 对象；大纲被包在别的对象里时（如 `{"outline": {…}}`）照样取出。没闭合的思考块、多个完整的大纲 JSON 对象、JSON 不完整时不采用。

提取后整理模型的输出：忽略多余字段，超长的文字截到上限，超出项数的约束、阶段和剧情要点只保留前面的，阶段数与要求不一致时照常保存；这些调整列在草稿上方，随这份草稿显示（只记在当前页面，草稿被替换或刷新页面后不再显示）。缺少必填内容（如阶段目标、推进条件）、类型错误，或大纲 JSON 超过 48000 字符（包括空白，见「长度」）时报错，指出具体字段，例如 `chapters[1].approach` 指第 2 阶段的「发展方式」。出错不替换已有的草稿和规划，也不自动重试。

用户手动编辑保存时仍用严格的检查：多余字段、超长、数量超出都会报错并定位到对应阶段，不会自动截断。

## 角色的反应

生成规划和引导正文时均强调：角色按自身的性格、动机、顾虑和已知信息行动，情绪和关系延续前文。允许犹豫、拒绝、误解和暂无结果的互动，不为推进剧情节点而突然配合、坦白、和解或翻脸，也不依靠口癖、小动作、争吵或长篇心理描写营造「活人感」。剧情节点可因人物的合理反应推迟、调整或不实现。

## 保护

- 草稿和正在使用的规划分开保存。
- 取消、切换聊天，或生成期间修改了正文或草稿时，迟到的结果不会覆盖当前内容；读取世界书期间发生这些变化时，不发送请求。
- 正常继续聊天不影响规划；改写、重抽或删除规划参考过的正文后，规划暂停生效，酒馆中弹出一次提示，规划卡片和「创作规划」折叠行显示「剧情有改动，已暂停」，需核对后点击「核对后重新启用」。
- 保存失败时保留原有数据；无法识别数据版本时只读保护。
- 数据存于聊天元数据的 prism_book_outline（规划）和 prism_book_outline_discussion（讨论）。讨论记录自 prism.15 起保存每条消息的时间（第 2 版格式），之前的记录没有时间；旧版本打开带时间的讨论时只读保护，不会覆盖。规划专用 API 的设置和自动检查的开关存于扩展设置的 prism_book_outline_settings。密钥保存在酒馆的扩展设置（settings.json）中，分享 settings.json 或截图前需删除或遮盖；用「设置备份」导出的文件已去掉密钥。
