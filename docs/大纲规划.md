# 大纲规划：从剧情与输入到计划

入口在 **摘要 → 计划 → 创作规划 / 大纲规划**，不是札记里的新 Q，也不新增独立导航页。

## 使用流程

1. 输入希望接下来怎样发展、节奏、必须保留的伏笔及不希望发生的事，选择规划阶段数量。
2. 点击生成。模型会只读近期剧情、用户原话、已有摘要压缩层（含 L1/L2）、人物与物品等当前状态，结合本次输入给出草稿。
3. 编辑总体方向、持续约束及每阶段的 **剧情要点、发展方式、推进条件**。
4. 保存草稿后，明确确认「加入计划」。确认前不会影响正文；新生成的草稿也不会替换之前正在使用的规划。
5. 正常回酒馆发送消息或续写。宝书会把总体约束和当前阶段注入给正文模型，不替用户自动发送消息或连续生成。下一阶段由用户切换，可随时暂停。

大纲是创作指引，不保证所有模型每轮都严格遵循。最新用户指令及已有剧情事实优先，不能为了落实大纲替用户角色作决定。若剧情已经明显偏离，可按新输入重新规划，核对后替换。

## 与模型讨论大纲

在【计划】的大纲区域打开 **与模型讨论大纲**。选择参考“已确认规划”“已保存草稿”或“先讨论方向”，输入意见后发送。讨论使用当前保存的规划 API 配置（默认复用札记，也可专用），支持连续多轮商量人物动机、节奏与分支。

讨论回答只作为建议展示并保存，不会直接修改大纲，也不会成为正文、摘要或角色承诺。采用流程为：**讨论 → 按讨论生成草稿 → 确认生成修订草稿 → 核对编辑 → 确认加入计划**。修订另发一次 API 请求；即使生成成功，原已确认规划仍不变，直到你手动替换。

讨论只参考已经保存的版本，编辑器中的未保存修改不会偷偷发给模型。讨论记录存于本聊天独立的 `prism_book_outline_discussion` 元数据，刷新可重载，切聊天不串记录；清空讨论需确认，且不删除大纲、札记或摘要。

每次问题最多4000字符、回答8000字符，保留最多12轮、合计48000字符，超限明确拒绝，不静默删除旧记录。请求参考最近24000字符的完整问答，较早意见可能不在模型窗口内；重要要求请在最新一轮重申。切聊天、正文或大纲在请求期间变化会丢弃迟到回复；失败保留已有讨论，不自动重试。支持取消，模型回答以纯文本呈现，不执行其HTML或操作指令。

## 与原有「计划」的区别

同一个计划面板中，**剧情内计划**来自正文中的真实打算、约定；**创作规划**来自用户确认的未来写作方向。两者都可以在计划区查看，但不会混为同一种事实。

确认后的规划保存在本聊天的独立 `prism_book_outline` 数据中，计划区直接读取该真源。不复制进正文叶子的 `plans.add`，不改旧摘要、角色承诺、物品记录或 L1/L2，也不要求先生成摘要才能保存规划。这样重建摘要不会把未来大纲当历史重放，也不会擦掉规划。

当前阶段才参与正文注入，后续阶段不提前泄露。切换或结束阶段只是用户管理规划进度，**不代表那些剧情已经发生**。摘要仍然只根据正文中真正发生的事件记录变化。

## API 配置

默认复用札记已保存的 API 地址、密钥、模型及请求参数，但使用大纲自己的提示词和数据，**无需启用札记生成开关**。也可切换为大纲专用 OpenAI 兼容 API，单独拉取模型列表、搜索选择或手动填模型。

不会回退正文或摘要 API。生成由用户手动触发，不自动重试或自动连续规划。专用设置保存在 `prism_book_outline_settings`；分享酒馆设置备份前请移除密钥。

大纲内容长度限制与 API 输出 token 上限是两回事。放宽内容限制不会自动修改已有渠道的 maxTokens；若回复被截断，请减少阶段数量或在实际使用的渠道中调整输出额度。复用札记时调整札记 API，专用模式调整规划 API；是否支持更大输出取决于模型与服务商。

## 角色的活人感

规划生成与正文注入同时强调：角色依据已有性格、独立动机、顾虑、边界和实际知情范围行动，情绪与关系需要承接前文。允许符合处境的迟疑、拒绝、误解、改口及没有立即结果的互动，不默认配合主角或为推进节点突然坦白、和解、翻脸。

这不是要求人物处处抵抗，也不靠统一口癖、小动作、争吵或冗长心理剖白制造“活人感”。节点应为人物合理反应让步，可以延后、调整或不兑现；不得替用户角色决定言行，也不把规划中的动机说明直接变成台词。规则通用于不同故事，不绑定测试场景。提示词约束已接入不等于真实模型表现已验收。

## 长度与报错

总 JSON 上限为 **48000 字符**，含 JSON 标点、空白；原始回复含思考块和包装最多100000字符。标题最多240字，整体方向4000字，每条约束1200字；每阶段目标2400字、发展方式3200字、单条要点1600字、推进条件2000字。技术上按 UTF-16 字符单元计数，少数表情符号会占两个单元；这些数字不是 token 数。

各字段上限并非推荐写满的篇幅。正文只接收当前阶段和全局约束，含固定指引总计最多16000字符；超限仍可保存草稿，但需要精简才能启用，不会悄悄丢弃约束或替换现有规划。

模型回复与编辑保存共用校验，错误会指出已知字段路径、缺失项、类型、长度或数量问题（例如 `chapters[1].approach` 代表第2阶段的发展方式）。语法不完整、额外字段仍拒绝；兼容单个 json / 无语言标签代码围栏，不从混杂正文中强行提取或补造内容。错误不显示原始模型回复、未知字段名或服务端异常；生成失败不替换旧草稿和已确认规划，不自动重试。

## 保护与限制

- 每份规划仍为 1～12 阶段，每阶段 1～8 个剧情要点；扩容不更改旧数据格式，已有大纲、札记及 L1/L2 无需重建。
- 生成、编辑后的草稿与已确认规划分开保存；草稿替换不自动改变当前指引。
- 取消、切聊天、生成期间编辑正文或修改草稿后，迟到的生成结果不覆盖新状态。
- 普通追加剧情不会让现有规划失效；改写、重抽、删除其参考的历史正文会停止注入，须用户核对后重新启用。
- 保存失败保留原数据，可重试；未知数据版本进入只读保护，不自动覆盖。
- 只支持本地模拟宿主验证，不代表已经在所有酒馆版本、预设和手机上实机验收。
