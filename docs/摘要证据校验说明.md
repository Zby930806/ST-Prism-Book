# 摘要报错：原句核对与没写入的更新

## 哪些内容要附原句

- 改名接续（npcs.rename）：附本楼正文中含新名字的连续原句。
- 记录冲突（conflicts）：附本楼正文中与记录矛盾的连续原句；对不上的冲突提示直接不收，不影响这一楼保存。
- 回看原文补档案、角色重新建档：每个字段附摘录中的原句。

角色位置自 1.4.4 起不再要求附原句（locationEvidence）。这项要求原本用来防止把被提到、看见或打算前往的地点当成角色已经在那里，但模型给的引文常与正文对不上：合法的位置被去掉，第一次对不上还要整楼重发一次请求。现在按提示词规则直接记录：正与主角当面互动的角色，位置通常就是主角所在地点；只被提起或远程联络的角色，正文没交代所在就不记位置；主角换了场景而角色没有同行时，不重报旧地点，由插件标为「位置未确认」。模型照旧写法附的原句不会写入记录。

伤势和身体状态（condition）自 1.4.2 起整段覆盖：有变化时写变化后的完整状态，不需要附原句或片段编号。此前的「局部更新」（conditionPatch）要求每一处删改都附本楼原句，正文没有明说已经好了的旧伤无法删除，伤情记录越积越长，因此撤回。模型仍按旧写法输出的伤情补丁会被直接去掉，不影响这一楼保存。旧聊天里已保存的伤情不受影响，不需要重新摘要。

状态清单（stateChanges）自 1.4.4 起停用：以前要求模型列出本楼更新了哪些字段，与实际输出对不上就整楼重发；现在不再要求，旧模板仍输出时直接忽略。

## 原句的核对方式

- 只在该楼清理后的原文中查找。发给模型的请求文本（带来源编号和说明）不作为原文，多条消息拼接也不作为证据。
- 允许的差异：中文排版中的空格和换行、成对的 Markdown 强调符号、全角与半角标点、不同样式的引号（如“”与「」）、省略号和破折号的不同写法，以及给整句原话额外加的一对引号。
- 不通过的情况：改字、改用别的标点（如逗号改顿号）、删除否定词、在句中加引号或省略号、把不相邻的句子拼起来。
- 改名的原句必须含新名字。

## 不合格时的处理

1. 前几次不合格：带着出错的项目和序号重新请求，次数按「设置 → 摘要设置 → 失败重试次数」（默认 1 次）。
2. 最后一次仍不合格：只去掉不合格的那几项，这一楼的摘要和其他状态照常保存。提示逐项写明原因：没有给出正文原句、给出的原句与本楼正文对不上，或编号、字段不符合要求。例如「楼层 #34 的摘要已保存，以下 1 项更新没有写入，原记录保持不变：改名「酒保A → 老周」（给出的原句与本楼正文对不上）。」被去掉的项目保持原有记录，并列在楼层面板该楼的「没写入的内容」中；需要时可在「角色」页手动修改，或在楼层面板重新生成本楼摘要。
3. 物品、计划、生活档案等更新缺少必填内容或编号不存在，在最后一次同样只去掉该项。只有回复中没有可解析的 JSON 或缺少 summary 时，这一楼才不保存，保留原有摘要和状态；批量补摘在这一楼停止，以免后续楼层使用错误的前序状态。
4. 以前保存的楼层，「没写入的内容」中可能列有位置项（1.4.4 之前，如「某角色的位置（给出的原句与本楼正文对不上）」）、状态清单项（1.4.4 之前）或伤情项（1.4.2 之前），属于当时的记录，重新生成该楼摘要后不再出现。

## 重新摘要

- 没有摘要的楼层：点击摘要页上方的「补摘」，或在「未摘要楼层」中点击楼层号单独补摘。
- 已有摘要需要重做时：在「设置 → 基本设置」中启用楼层面板，在该楼点击重新生成；新结果先与现有摘要并排对比，选择「用新的」后才替换。无需全部重新摘要，也无需重新生成旧的 L1/L2。
- 仅在修改了早期剧情、需要从该处重新推算后续状态时，才需要全部重新摘要（摘要页概览的「全部重新摘要…」，可以从修改处的楼层开始）。

该检查只能证明原句出自正文，不能证明原句支持对应的改动。
