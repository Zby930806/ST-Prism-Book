# 摘要报错：伤势和位置的证据

## 为什么要附原话

记录伤势和身体状态时，摘要使用「局部更新」（conditionPatch）：只修改有新依据的部分，保留旧伤和行动限制。每一项都需填写状态文字，并附本楼正文中的原话作为证据；替换旧的某一段时，还需填写该段编号。角色位置变化也需附原话（locationEvidence）。

## 原话的核对方式

- 只在该楼清理后的原文中查找。发给模型的请求文本（带来源编号和说明）不作为原文，多条消息拼接也不作为证据。
- 允许的差异：中文排版中的空格和换行、成对的 Markdown 强调符号、全角与半角标点、不同样式的引号（如“”与「」）、省略号和破折号的不同写法，以及给整句原话额外加的一对引号。
- 不通过的情况：改字、改用别的标点（如逗号改顿号）、删除否定词、在句中加引号或省略号、把不相邻的句子拼起来。
- 位置的原话照录正文对该角色的称呼即可，不必出现名册里的名字。例如名册中记为「敲门鬼」的角色，正文写「门外又响起了敲门声」，就照录这句。

## 不合格时的处理

1. 前几次不合格：带着出错的人物和项目序号重新请求，次数按「设置 → 摘要设置 → 失败重试次数」（默认 1 次）。
2. 最后一次仍不合格：只去掉不合格的那几项，这一楼的摘要和其他状态照常保存。提示逐项写明原因：没有给出正文原句、给出的原句与本楼正文对不上，或编号、字段不符合要求。例如「楼层 #34 的摘要已保存，以下 1 项更新没有写入，原记录保持不变：敲门鬼的位置（给出的原句与本楼正文对不上）。」被去掉的项目保持原有记录，并列在楼层面板该楼的「没写入的内容」中；需要时可在「角色」页手动修改，或在楼层面板重新生成本楼摘要。
3. 伤情补丁的编号不存在、字段不对或放错位置，以及物品、计划、生活档案等更新缺少必填内容或编号不存在，在最后一次同样只去掉该项。只有回复中没有可解析的 JSON 或缺少 summary 时，这一楼才不保存，保留原有摘要和状态；批量补摘在这一楼停止，以免后续楼层使用错误的前序状态。

## 重新摘要

- 没有摘要的楼层：点击摘要页上方的「补摘」，或在「未摘要楼层」中点击楼层号单独补摘。
- 已有摘要需要重做时：在「设置 → 基本设置」中启用楼层面板，在该楼点击重新生成；新结果先与现有摘要并排对比，选择「用新的」后才替换。无需重建整个聊天，也无需重新生成旧的 L1/L2。
- 仅在修改了早期剧情、需要从该处重新推算后续状态时，才需要重建。

该检查只能证明原话出自正文，不能证明原话支持对应的伤势或位置变化。
