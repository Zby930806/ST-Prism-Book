# 摘要报错：伤势和位置的证据

## 为什么会报错

记录伤势和身体状态时，摘要用的是「局部更新」（conditionPatch）：只改有新依据的部分，旧伤和行动限制会保留。每一项都要写状态文字，并附上本楼正文里的原话作为证据；要替换旧的某一段，还要写它的编号。角色位置的变化也要附原话。

如果模型给的原话在正文里找不到、字段缺了、类型不对、编号错了，或者补丁放错了位置，这一楼的摘要就不会保存。页面会说明是哪个人物、第几项出了问题。

## 怎么核对原话

- 只在这一楼清理后的原文里找。不会拿发给模型的请求文本（带来源编号和说明）当原文，也不能把几条消息拼起来当证据。
- 能容忍成对的 Markdown 强调符号、中文排版里的空格和换行；改字、改标点、删掉否定词、拼接都不算数。
- 失败后按设置里的「失败重试次数」再试，不会无限重试。

## 失败了怎么办

- 失败的那一楼保留原来的摘要和状态，不会被覆盖。批量补摘会在失败的那一楼停下，免得后面的楼用错前面的状态。
- 没有摘要的楼层，点摘要页上方的「补摘」，或者在「未摘要楼层」里点楼层号单独补；已有摘要想重做，在「设置 → 基本设置」里打开楼层面板，到那一楼点重新生成。不需要重建整个聊天，旧的 L1/L2 也不用重新生成。
- 只有改了早期剧情、需要从那里往后重新推算状态时，才需要重建。

这个检查只能证明原话确实出自正文，不能证明原话真的支持那个伤势变化，模型仍然要按原文来写。也不能保证所有模型都不会报错。
