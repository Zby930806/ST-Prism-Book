# 摘要证据校验与恢复

## 伤势为何会报错

conditionPatch 是身体状态的局部更新协议，用于保留旧伤、活动限制，只修改有新依据的部分。每项包含状态文字 text 与本轮正文引文 evidence；替换旧片段还需 id。不能为了不报错就丢弃状态更新，或只保存摘要造成记录不同步。

本次修复：
- 伤情与角色位置共用保守的引文匹配，容忍成对 Markdown 强调、中文排版空白及换行；仍拒绝改字、改标点、删否定、拼接和合并英文单词。
- 正式摘要入口在清理后的原消息内校验，不再拿附有来源编号与程序说明的模型请求文本充当原文。不同消息不能拼接成证据。
- 漏字段、类型错误、错误编号与引文不匹配分别给出具体人物和操作索引，沿用用户配置的有限纠错次数，不额外无限调用。
- 放错位置的伤情补丁明确拒绝，不由解析器静默吞掉。
- 摘要页面显示失败楼层和恢复方法，技术原因折叠展示。校验失败不覆盖该楼旧摘要/状态；批量任务在失败楼停止，避免后楼用错前置状态。

## 恢复方法

缺失楼层使用「补录摘要（AI）」；已有摘要要替换时对该楼重新摘要。普通格式/证据失败无需重建整个聊天，也不会要求1800楼的旧L1/L2重新生成。若修改了早期剧情事实并需要重新推导后续状态，这是另外的重建场景。

此校验只能证明引文来自正文，不能自动证明语义上支持伤情变化；模型仍须遵守原文依据规则。真正没有证据的输出仍会被拒绝，不能承诺所有模型永不报错。

本地验证使用模拟数据与模拟模型返回；用户截图没有完整模型返回，本次不能断言截图具体属于漏字段、排版或内容不匹配中的哪一种。
