# 发布与安装

文件名沿用以前的，免得已有链接失效。仓库按维护者的决定公开。

## 上传到仓库

用 git 推送或者网页上传都可以。注意：

1. 仓库根目录要直接包含 manifest.json、README.md、src、dist 等；dist 里要有 index.js、index.css 和 index.js.map。
2. 源码、dist 和 manifest 必须是同一个版本，不能只传源码。
3. 不要上传聊天、settings.json、.env、密钥、node_modules、备份和本机的验证记录，也不要只传一个 ZIP。
4. 提交前看一下文件列表。`pnpm release:check` 会检查版本是否一致、根目录有没有多余文件、有没有疑似密钥。

## 安装和更新

在酒馆的扩展面板点「安装扩展」，粘贴仓库地址即可；更新在「管理扩展」里操作。手动安装见 README。不要同时启用原版和本版，它们用的是同一份数据、宏和事件。

接续旧聊天前先看 [旧记忆接续说明](LEGACY-COMPATIBILITY.md)：已知的 V3 直接读取，能确定对应关系的 V2 在本地转换，认不出的格式只读保护。升级不需要重建。

「重建本聊天记忆」保留了，但不会自动执行：需要你手动确认，它会按楼层顺序请求模型、可能产生费用，并替换已有的摘要和手动改过的状态。用之前先备份。

## 不做的事

不启用上游的一键更新，也没有 GitHub Pages、自动 Release 或自动部署。package.json 里的 private: true 只是防止误发布到 npm，和仓库是否公开无关。

公开仓库里不要放授权聊天截图、私人联系方式或令牌。
