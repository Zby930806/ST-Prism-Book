# 发布与安装

文件名沿用旧名，以免已有链接失效。仓库按维护者的决定公开。

## 上传到仓库

可通过 git 推送或网页上传。要求：

1. 仓库根目录直接包含 manifest.json、README.md、src、dist 等；dist 中包含 index.js、index.css 和 index.js.map。
2. 源码、dist 和 manifest 版本必须一致，不能只上传源码。
3. 不上传聊天、settings.json、.env、密钥、node_modules、备份和本机验证记录，也不能只上传一个 ZIP。
4. 提交前检查文件列表。`pnpm release:check` 检查版本是否一致、根目录是否有多余文件、是否有疑似密钥。

## 安装和更新

在酒馆扩展面板中点击「安装扩展」，填入仓库地址；更新在「管理扩展」中进行。手动安装见 README。原版和本版共用同一份数据、宏和事件，不能同时启用。

接续旧聊天前参阅 [旧记忆接续说明](LEGACY-COMPATIBILITY.md)：已知的 V3 格式直接读取，可确定对应关系的 V2 格式在本地转换，无法识别的格式只读保护。升级无需重建。

「重建本聊天记忆」保留，但不会自动执行：需手动确认，执行时按楼层顺序请求模型，可能产生费用，并替换已有摘要和手动修改过的状态。使用前先备份。

## 不做的事

不启用上游的一键更新，不提供 GitHub Pages、自动 Release 或自动部署。package.json 中的 private: true 仅用于防止误发布到 npm，与仓库是否公开无关。

公开仓库中不放置授权聊天截图、私人联系方式或令牌。
