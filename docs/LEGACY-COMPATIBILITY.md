# 从柏宝书接续旧聊天

适用版本：1.2.9-prism.2 / 1.2.9-prism.3。目标是沿用已有逐楼摘要、状态和 L1/L2 等上层总结，不因更换插件品牌重新处理整段历史。

## 三种检查结果

| 摘要页状态 | 行为 | 你需要做什么 |
| --- | --- | --- |
| 可直接沿用 | 读取已知 V3 数据；加载本身不保存、不转换、不请求模型 | 核对旧摘要与总结，继续聊天，无需重建 |
| 需要本地转换 | 已知 V2，且每条旧逐楼摘要能唯一对应一个现存 AI 楼、第一页及状态记录 | 先备份，再点摘要页的本地转换并确认；只转换存储结构，不请求模型 |
| 旧记忆保护中 | 未知版本、不完整摘要、无法确定的分页、损坏引用或不明确的旧覆盖范围 | 保留原聊天，不全量重建；导出后交给维护者检查 |

不能自动转换的例子：V2 一条摘要覆盖多楼、目标楼已删除、目标楼已有另一条摘要、状态变化含无法完整重放的未知指令，或旧摘要未标分页而当前已翻到其它回复。普通扩展字段保留在节点上；delta 内的未知字段不猜测为有效状态。不能把这些记录当作“没有摘要”从头调用 AI。

保护模式会暂停本插件的记忆写入、补摘、总结及记忆注入，并拦住正常自动生成路径，避免静默覆盖或带着错误记忆续写。Horae 导入和带数据创建新聊天同样不能绕过保护。它不是让两个插件同时运行的锁；关闭自动摘要或使用其它生成路径不等于本插件已确认记忆安全。

## L1 / L2 会不会发给模型？

会参与实际上下文选择，而不只是展示在摘要页：

- **正文 AI**：对已隐藏的历史楼层，选取能完整代表其内容的最高有效总结。
- **摘要 AI**：对本次目标楼之前的历史，也使用最高有效总结。
- 已选择 L2 时，不再把同一覆盖范围的 L1 和逐楼摘要重复注入；不能完整覆盖时回退到有效下层。
- 注入开关、隐藏窗口及 token 预算仍然生效。不是承诺把 1800 楼的所有原文和所有层级无截断一起发送。
- 摘要接续保留既有文字，不会靠重新生成来“适配新提示词”。状态按已存变化记录重放，不等于重新请求模型。

## 更新步骤

1. 导出重要聊天，并备份酒馆数据、设置与旧插件目录。
2. 关闭酒馆，把旧插件移到 extensions 之外；保留备份，不要同时启用柏宝书与棱镜宝书。
3. 安装完整候选文件夹，确认根目录有 manifest.json 和 dist。
4. 启动并强制刷新，进入旧聊天的摘要页，查看兼容提示与已有总结。
5. 直接沿用型不点重建；需转换型确认本地转换。转换保存期间不要切换聊天、编辑或翻页。
6. 先在聊天副本验证新增一楼：旧摘要仍在，新增摘要对应新楼，实际提示词中的历史层级没有父子重复。不要直接拿唯一的长聊天试验。

保留的数据与接口名称包括 baibai_book、bbs_leaf 和原公共 API。这是数据连续性的需要，不是品牌替换遗漏。

## 本地转换的保存与失败

转换会先在聊天元数据的 prism_book_legacy_backup 中保存旧结构并等待宿主保存成功，再写转换后的叶子及总结。已有备份不会被覆盖。转换不删除摘要文字、ID 或已保存的状态变化。

宿主的聊天保存与元数据保存是两个接口，不是跨文件原子事务。保存失败或期间切换聊天时，插件停止后续写入，恢复所持内存记录并保留备份；这**不能保证磁盘也已完全回滚**。出现错误先导出核对，不要删除备份、盲目重试或全量重建。

## 费用、重建与回退

- 安装和兼容检查不请求模型；本地结构转换也不请求模型。
- 新增剧情按原有规则摘要；达到阈值时可能另做上层压缩总结。向量功能启用后也可能请求嵌入服务。这些不等于重摘旧 1800 楼，不承诺日常续写永远只有一笔请求。
- “重建本聊天记忆”仍保留为手动功能。它会调用 AI，可能收费，会逐楼替换摘要和状态更新；失败或取消可能留下部分已重建内容。**升级不需要重建。**
- 请求期间切换聊天后，旧结果不得写入新聊天；向量召回也在各异步步骤核对归属。已经发出的请求不能保证撤回或免除服务端费用。
- 不支持两个版本同时写同一聊天；未实现双插件互斥检测。
- 不承诺任意旧版都支持转换后格式。要回退，使用转换前导出的聊天、设置和插件备份，不要仅替换插件文件就假定数据双向兼容。

## 本轮验收边界

自动化覆盖合成的 1800 条旧摘要、60 个 L1、6 个 L2，正式选择器/注入链路，异常格式与分页保护，本地转换保存失败以及异步请求切聊天等场景。

这些结果是程序与存储格式层的证据；真实酒馆版本、用户的真实 1800 楼聊天、实际接口发出的上下文、模型续写质量和界面布局尚需在聊天副本实测。测试未操作运行中的酒馆，也未调用真实模型；发布到仓库不代表已通过用户真实聊天的实机验收。
