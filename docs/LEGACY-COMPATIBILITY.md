# 从柏宝书接续旧聊天

适用于 1.2.9-prism.2 及之后的版本。换成棱镜宝书后，旧聊天的逐楼摘要、状态和 L1/L2 等总结直接沿用，不需要重新处理整段历史。

## 摘要页会显示三种状态

| 状态 | 是什么情况 | 你要做什么 |
| --- | --- | --- |
| 记忆正常 | 已知的 V3 格式，直接读取；打开时不保存、不转换、不请求模型 | 核对一下旧摘要和总结，接着聊，不用重建 |
| 需要转换 | 已知的 V2 格式，而且每条旧逐楼摘要都能对上一条现存的 AI 楼、第一页和状态记录 | 先备份，再在摘要页点「备份并转换…」。只转换存储格式，不请求模型 |
| 只读保护 | 版本未知、摘要不完整、分页对不上、引用损坏，或者旧的覆盖范围说不清 | 不要重建，保留原聊天，导出后交给维护者检查 |

不能自动转换的例子：一条 V2 摘要覆盖了好几楼、对应的楼已经删了、那一楼已经有另一条摘要、状态变化里有无法重放的未知指令，或者旧摘要没标分页而现在已经翻到了别的回复。这些记录不会被当成「没有摘要」从头请求 AI。

只读保护期间，本插件的记忆写入、补摘、总结和记忆注入都会暂停，正常的自动生成也会被拦下，免得悄悄覆盖数据，或者带着错误的记忆续写。Horae 导入和带数据创建新对话也绕不过去。这个保护不能让两个插件同时运行。

## L1 / L2 会发给模型吗

会，不只是在摘要页显示：

- 正文模型：已经隐藏的旧楼层，用能完整代表它们的最高一层有效总结代替。
- 摘要模型：本次要摘的楼之前的历史，也用最高一层有效总结。
- 用了 L2，就不会再重复发同一范围的 L1 和逐楼摘要；覆盖不完整时退回下一层。
- 注入开关、隐藏的楼层数和预算仍然有效，不会把 1800 楼的原文和所有层级一起发出去。
- 旧摘要的文字保持原样，不会为了适配新提示词重新生成。状态按已存的变化记录重新计算，这一步不请求模型。

## 升级步骤

1. 导出重要的聊天，备份酒馆数据、设置和旧插件目录。
2. 关掉酒馆，把旧插件移到 extensions 目录外面。不要让柏宝书和棱镜宝书同时启用。
3. 安装棱镜宝书，确认插件文件夹第一层有 manifest.json 和 dist。
4. 启动并强制刷新，打开旧聊天的摘要页，看兼容状态和已有的总结。
5. 「记忆正常」就不要点重建；「需要转换」就确认转换，保存期间不要切换聊天、编辑或翻页。
6. 先在聊天副本上新聊一楼试试：旧摘要还在，新摘要对应新的一楼，发给模型的历史没有重复。不要直接拿唯一的长聊天来试。

数据和接口沿用原名（baibai_book、bbs_leaf 和原来的公共 API），是为了让旧数据直接接上，不是改名时漏掉了。

## 转换时怎么保存

转换前会把旧结构备份到聊天元数据的 prism_book_legacy_backup，等酒馆保存成功后，才写入转换后的摘要和总结。已有的备份不会被覆盖。转换不会删除摘要文字、ID 或已保存的状态变化。

酒馆的聊天和元数据是分开保存的，没法保证两边同时成功。保存失败或期间切换了聊天时，插件会停止后续写入、恢复内存里的记录并保留备份，但**不能保证磁盘上也完全回滚**。出现错误时先导出核对，不要删除备份、反复重试或者重建。

## 费用、重建和回退

- 安装、兼容检查和本地转换都不请求模型。
- 新的剧情照常摘要，攒够了会合并成总结；开着向量记忆时还会请求 embedding 服务。这些都不会重摘旧楼层。
- 「重建本聊天记忆」仍然保留在摘要页底部。它会请求 AI，可能产生费用，会一楼一楼替换摘要和状态；失败或取消时可能只重建了一部分。**升级不需要重建。**
- 请求期间切换聊天，旧结果不会写进新聊天。已经发出去的请求没法撤回，服务端可能照样计费。
- 不支持两个版本同时写同一个聊天，也没有做互斥检测。
- 想退回旧版，请用转换前导出的聊天、设置和插件备份，不要只换插件文件就以为数据能来回兼容。

## 测试范围

自动测试用合成数据覆盖了 1800 条旧摘要、60 个 L1、6 个 L2，以及实际的选择和注入流程、异常格式和分页保护、转换时保存失败、请求期间切换聊天等情况。这些是程序和存储格式层面的验证；真实的酒馆版本、你自己的长聊天、实际发出去的上下文和续写质量，还需要在聊天副本里实测。
