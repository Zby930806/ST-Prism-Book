# 从柏宝书接续旧聊天

适用于 1.2.9-prism.2 及之后的版本。改用棱镜宝书后，旧聊天的逐楼摘要、状态和 L1/L2 等总结继续使用，无需重新处理整段历史。

## 摘要页的三种状态

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 记忆正常 | 已知的 V3 格式，直接读取；打开时不保存、不转换、不请求模型 | 核对旧摘要和总结后继续聊天，无需重建 |
| 需要转换 | 已知的 V2 格式，且每条旧逐楼摘要都能对应一条现存的 AI 楼、第一页和状态记录 | 先备份，再在摘要页点击「备份并转换…」。只转换存储格式，不请求模型 |
| 只读保护 | 版本未知、摘要结构不完整、引用损坏，或旧的覆盖范围无法确定 | 不要重建，保留原聊天，导出后交由维护者检查。只因总结引用了已不存在的楼层而保护时，可按下文清理 |

无法自动转换的情况：一条 V2 摘要覆盖多楼、对应楼层已删除、该楼已有另一条摘要、状态变化中有无法重放的未知指令，或旧摘要未标注分页而当前已翻到其他回复。这些记录不会被视为「没有摘要」而重新请求 AI。

只读保护期间，本插件的记忆写入、补摘、总结和记忆注入均暂停，正常的自动生成也会被拦截，以免静默覆盖数据，或带着错误的记忆续写。Horae 导入和带数据创建新对话同样受此限制。此保护机制不支持两个插件同时运行。

## 残缺的总结和未记录分页的旧摘要

总结引用了当前聊天里已经不存在的楼层、其余结构都正常时（多为删除楼层，或从较早的楼层开分支、建检查点后留下），处理方式如下：

- 分支和检查点：酒馆会把原聊天的全部总结复制过来，消息却只保留到分支点。打开时自动从这个分支删除包含分支点之后楼层的总结（连同包含它们的上层总结），并弹出提示；逐楼摘要和其余总结保留，之后按设置重新合并。原聊天不受影响。
- 其他聊天：仍进入只读保护。先用酒馆的「管理聊天文件」导出聊天，再在摘要页点击「清理残缺的总结…」，处理方式同上。清理后合并总结可能产生请求。

版本未知、重复 ID、循环引用、层级倒置等损坏不提供清理，仍整段保护。

旧摘要未记录分页、而这一楼当前翻到了其他回复时，只冻结这一楼：这一页不摘要、不注入，也不覆盖旧摘要，翻回第一页即恢复，不再锁定整段聊天。

## L1 / L2 会发给模型吗

会，不只在摘要页显示：

- 正文模型：已隐藏的旧楼层，以能完整代表它们的最高一层有效总结代替。
- 摘要模型：本次摘要楼层之前的历史，同样使用最高一层有效总结。
- 使用 L2 后，不再重复发送同一范围的 L1 和逐楼摘要；覆盖不完整时退回下一层。
- 注入开关、隐藏楼层数和预算仍然有效，不会将 1800 楼的原文和所有层级一起发送。
- 旧摘要的文字保持原样，不会为适配新提示词而重新生成。状态按已保存的变化记录重新计算，此步骤不请求模型。

## 升级步骤

1. 导出重要的聊天，备份酒馆数据、设置和旧插件目录。
2. 关闭酒馆，将旧插件移出 extensions 目录。柏宝书和棱镜宝书不能同时启用。
3. 安装棱镜宝书，确认插件文件夹第一层包含 manifest.json 和 dist。
4. 启动酒馆并强制刷新，打开旧聊天的摘要页，检查兼容状态和已有的总结。
5. 状态为「记忆正常」时不要重建；状态为「需要转换」时确认转换，保存期间不要切换聊天、编辑或翻页。
6. 先在聊天副本上新生成一楼进行测试：旧摘要仍在，新摘要对应新的一楼，发给模型的历史没有重复。不要直接使用唯一的长聊天测试。

数据和接口沿用原名（baibai_book、bbs_leaf 和原有的公共 API），用于直接兼容旧数据，并非改名遗漏。

## 转换时的保存方式

转换前将旧结构备份到聊天元数据的 prism_book_legacy_backup，酒馆保存成功后才写入转换后的摘要和总结。转换不删除摘要文字、ID 或已保存的状态变化。

上次转换没有保存成功留下的备份，与当前旧记录完全相同时，再次转换直接沿用这份备份；不同时不转换，提示先导出聊天核对，确认不再需要那份备份后，可在摘要页点击「替换旧备份并转换…」。

酒馆的聊天和元数据分开保存，无法保证两者同时保存成功。保存失败或期间切换了聊天时，插件停止后续写入、恢复内存中的记录并保留备份，但不能保证磁盘上的数据完全回滚。出现错误时可重新载入聊天后在摘要页重试转换；仍失败时先导出核对，不要删除备份或重建。

## 费用、重建和回退

- 安装、兼容检查和本地转换均不请求模型。
- 新剧情照常摘要，摘要达到一定数量时合并为总结；启用向量记忆时还会请求 embedding 服务。这些操作都不会重新摘要旧楼层。
- 摘要页底部保留「重建本聊天记忆」。该操作会请求 AI，可能产生费用，并逐楼替换摘要和模型记录的状态；在各页面新增、修改、删除的物品、角色、地点等单独保存，重建后仍然保留。升级到 1.4.0 之前做的这类修改记在当时最新一条摘要里，重建时随那一楼的摘要一起替换。失败或取消时可能只完成部分重建。升级不需要重建。
- 请求期间切换聊天时，旧结果不会写入新聊天。已发出的请求无法撤回，服务端可能照常计费。
- 不支持两个版本同时写入同一个聊天，也没有互斥检测。
- 退回旧版时，需使用转换前导出的聊天、设置和插件备份；仅替换插件文件不能保证数据双向兼容。

## 测试范围

自动测试使用合成数据，覆盖 1800 条旧摘要、60 个 L1、6 个 L2，以及实际的选择和注入流程、异常格式和分页保护、转换时保存失败、请求期间切换聊天等情况。这些是程序和存储格式层面的验证；真实的酒馆版本、用户自己的长聊天、实际发送的上下文和续写质量，仍需在聊天副本中实测。
