═══ summary 怎么写 ═══
本楼隐藏以后，续写模型靠 summary 知道这里发生过什么。把它写成一段前情提要：按先后顺序，用完整的短句讲清谁做了什么、结果怎样、留下了哪些还在起作用的约定和限制。一般写到 {{summary_aim}} 字左右，最多不超过 {{summary_max_chars}} 字（含标点）；内容写清就停，不凑字数，很长的正文也可能几句话就够。
必须留下（篇幅不够时先删别的）：
- 改变局面的决定、行动和结果。之前提出的要求、约定或疑问在本楼被兑现、拒绝、取消或解开的，写出实际结果。
- 约定、承诺、条件、期限、保密要求和威胁，连同各自的条件与后果一起写：谁在什么条件下要做什么，否则怎样。
- 人名、地名、物品名、数字和时间，以及「没有」「尚未」「至少」「只有」「据某人说」这类否定和限定。
- 之后还会用到的话，用「」照抄原话并写明谁对谁说：承诺、条件、表白、拒绝、道歉、揭露秘密或关键情报的话、第一次改口的称呼。每楼一般引一两句，最多三句；寒暄、玩笑和叮嘱不引用。
- 人物之间有区别的具体互动：靠近、照顾、维护、回避、争执、和好，以及对方的回应。每楼留最有代表性的一两处，写动作本身（「她把椅子挪近，手搭在他手边」），不概括成「两人关系升温」。
- 亲密情节的硬事实:本楼正文明确写到发生性行为时,用一两句平实的话写清:谁和谁、当晚几次(正文写明才写)、每次是否戴套或用了别的避孕办法,未戴套或出了意外(如破损)时是否在体内结束,以及事后的处理和约定(买药、服药、约好以后必须戴套等);亲热中途停下没有做成的,写明没有做成和原因。这些与关键数值同等对待,不因属于过程或同类互动而省略,也不得只写成「发生关系」「共度一夜」。过程、姿势和感官描写不写,正文没写明的不猜。
可以删：重复的动作和检查、拿取收纳、赶路吃喝、环境与外貌描写，以及不影响后面的寒暄、小动作和生活细节。
写法：
- 只写正文里发生的事，写到最后一个动作或对话为止。不补后续，不写正文没有的情绪、动机和气氛（✗「气氛变得微妙」「这体现了他的在意」）。
- 不改变确定程度：打算、建议、听说、怀疑的事不写成已完成或已证实，别人说的事写明是谁说的；出发不等于到达，看见不等于身在其中。对方没有明说答应、拒绝或做完的，不替他下结论：只是开了句玩笑、没接话、换了话题，就照这样写；心里想的事不写成说出口的话。
- 不改动谁做了什么：主语、对象和先后照正文。一句话里换了人就把名字写出来，不让前半句的主语管到后半句；问的人和答的人不对调，一句原话只归说它的人。人名、地名、物品名照抄，不缺字、不改字。
- 时间写成固定的日期或时刻（如「三月初七清晨」），不用「今天」「昨晚」「三天后」这类会随阅读时间变化的说法；换算不了就保留和具体事件绑定的说法（「约在这次见面的次日」），不编日期。一楼里跨了几天的，每件事写在它发生的那天。回忆和闪回标明是回忆，不当作本楼发生的事。
- 一段连贯的叙述，不换行，不要标题、列表和 Markdown，也不出现「本楼」「原文」「摘要」这类指代材料的词。句子写完整，不为了省字把先后两个动作并成一个、弄错哪件事在前（上船前付的船钱，不写成「下船时付了船钱」）。
- 状态字段记下的内容，summary 里讲清经过就够，不用把每个字段再抄一遍；反过来，写进了 summary 也不能代替对应字段的更新。

  没有依据的一侧不填（不要默认填 0），null 表示撤回之前的估计。默认保持原档位：只有持续而清晰的新倾向、重大事件或对旧判断的明确纠正，足以说明原档位不再合适时才改；普通的夸奖、送礼、拌嘴、一次冷脸不改。内心和外在各自判断，可以不一致。affinityNote 用一句话写依据或表现，档位没变就沿用旧说明。估计不写进 summary 和 relation，也不代表别的人物知道。
位置（每楼都要核对，它决定续写时这个人算不算在场）：
- 待在某个地点的人：location 写那个地点，沿用「当前地点」或正文里的地名原文。正和{{user}}当面互动的人，location 通常就是{{user}}本楼所在的地点。
- 跟着{{user}}一起行动的同伴：follow: true，不写 location；新加入同行的人也这样写。
- 名册里每个人都带着本楼开始前的标记（〔在场〕〔同区域〕〔不在场〕〔当前位置未确认〕，同行的另标 [随行]）。对照本楼正文逐个看：
  · 标 [随行] 的人这次没有跟{{user}}走（被留下、自己留下、分头行动）→ follow: false，location 写他留下或去往的地点。只写 location 不写 follow: false，系统仍会当他在随行。
  · 有人离开或告别，正文没写去哪 → follow: false，location 填 ""（位置不明），不让他留在旧地点冒充还在。
  · {{user}}自己换了地方，原本待在某处的人没有跟来 → 不用为他写任何东西，系统会按他原来的位置处理。
  · 标〔不在场〕或〔当前位置未确认〕的人，只有本楼重逢，或正文写明他现在在哪时才更新（follow: true 或新的 location）。重逢要写进 npcs.update，不能只在 summary 里说他回来了。
  · 只被提起、通信或通话联系的人不算在场；正文没交代他在哪就不写 location。

【局势卡 sceneFocus】一小张「眼下正在发生什么」的快照，帮下一楼接上当前的场面，不是第二份摘要。要写就写完整的一张（整卡覆盖），situation 和 participants 必填：
- situation：本楼结束时的局面，一句话。日常戏写互动的氛围（「午后在厨房，她情绪有点低落，正教{{user}}做菜」），剧情戏写处境（「潜行中，刚被巡逻队发现」）。只写结束时的状态，不重述经过；听来的事写明来源（「据守卫说北门已封」）。
- participants：此刻在场的人，含{{user}}；要和上面核对过的位置一致，远程联络和只被提到的人不算。
- tension：明确而且持续的人际张力（冷战、尴尬、暗中较劲），没有就省略。pendingBeat：眼下这个场面里已经预告或启动、马上要发生的事（「她刚起身说去开门」），不预测，没有就省略；改天才兑现的约定写进 plans，不写在这里。
- 场面或在场的人换了、正在做的事换了、张力出现或解除时更新；同一场面里多说几句话、多做一个动作不更新。场面彻底结束写 "sceneFocus": null。

【物品 items】只记{{user}}持有或能支配的东西，不是所有人的财产表。
- 记什么：{{user}}实际得到（买、捡、收到、偷、做出来、借来），会带走或专门存放，而且对剧情有用的东西（能交易或使用、是线索、有情感价值、武器装备）。环境里的陈设、正穿着的衣服（写 outfit）、普通吃喝不记。别人之间的交易、报价和口头许诺不入库。
- add（本楼新得到）：qty 填这一次得到的数量，不是得到后的总数；同名旧物再得到也只填这次的量。数得清照填（三枚金币 → 3）。数不清的不猜数，按包装记 1 份：名字带上包装，多少写进 desc（「一袋碎银」→ 名字「钱袋」，qty 1，desc「装着些碎银」）。新物品要写 carried：带在身上（手里、口袋、随身的包、佩挂）填 true；不在身上填 false，并用 location 写它所在的地点。
- update（已有物品有变化）：用掉或给出一部分 → qty 填剩下的总数；原数量不清楚时不改数字，在 desc 里写还剩多少。放下、寄存、挪到别处或取回随身 → 改 carried 和 location。状态变了 → 改 desc。
- remove：整项用完、给出、归还或丢失。普通容器随内容物一起删，不留「空瓶」。
- 只结算本楼正文里新发生的事。「现有物品」已经是结算到本楼之前的结果，「近期物品变动」里的每一条都已经算过，不再算第二遍；本楼没有再次使用或得失，就不要动它。
- 库存里没有、本楼也没得到的东西被花掉或送出：只写进 summary，不为了记这笔支出去 add。

【计划与悬念 plans】只记要跨过当前场面、需要长期记住的事。大多数楼层不产生新条目，但每楼都要先核对旧条目。
核对「未了结的计划/悬念」（用编号 p1、p2…）：
- 已经兑现、揭晓、明确失败，被取消或撤回，或者因为客观事实再也不可能发生（如约定的对象已死）→ resolve，outcome 三选一：done 做成了或揭晓了；cancelled 取消、撤回、作废或不再需要；failed 试过但失败，或以坏结果收场。reason 用一句话写实际是怎么了结的。提出后当场被化解、对方让步或承认弄错的，是 cancelled，不是 done。
- 同一件事改期、暂缓或改了条件 → update，content 写改后的完整内容：只改有新说法的条款，其余仍有效的照抄（旧「三日内还清 50 金，逾期扣押马车」，债主同意宽限到七日 → 「七日内还清 50 金，逾期扣押马车」）；期限变了同时改 targetTime。
- 没提到、只是过了期限，或暂时受阻而结果未明 → 不动。时间流逝和人物离场都不等于了结。同一编号一楼里只能 update 或 resolve 一次。
新增（add）之前，先确认它和未了结、近期已了结的条目不是同一件事：
- 计划（kind 填 "plan"）：有人认真决定、承诺或约定将来要做的事，而且一两个回合内不会自然有结果（三日后决斗、铁匠答应改日交货）。客套话（「改天一定」）、气话、玩笑和马上就会发生的事不记。content 写清谁要做什么，以及条件和后果；createdTime 写立下它的故事内时间，targetTime 写目标时间，没有就省略。
- 悬念（kind 填 "suspense"）：正文明确留下的未知（身份、动机、真相、去向、异常的原因），或者已经启动、正在等结果的外部事件（追捕已经展开、毒会在七天后发作）。持续的状态、已经解释清楚的设定、内心的矛盾，以及「可能有危险」「矛盾还会持续」这类说法都不是悬念。同一个谜团多了线索或阶段进展，只写进 summary，不另加一条。

【信息差 secrets】记「某件事有人知道、某个已登场的角色不知道」，而且会影响后面言行的情况。只在两种情况下新增：正文写出有人刻意隐瞒、撒谎或叮嘱保密；或者一件要紧的事发生时某个已登场的角色明确不在场，事后也没有人告诉他。推测某人「可能不知道」、单纯的内心想法、设定里的背景不记。
- add：content 用一句话写客观事实，同一件事只记一条；knownBy 写知情的人，unaware 写不知情的人（至少一个）。只写主角或已登场角色的名字，主角写{{user}}。
- 正文写出有人得知、被告知、撞见或识破 → update（用编号 s1、s2…），给出更新后的完整 knownBy 和 unaware；所有相关的人都知道了 → resolve。时间过去、离场、猜测都不等于得知。

【生活小档案 lifeDetails】{{user}}和主要角色的偏好、习惯和近期的个人状态，只记本人明说或正文明确写出的；一次行为不等于习惯（吃了一次煎饼不等于爱吃煎饼），玩笑、转述和猜测不算。路人不记。
- add：subject 写这条属于谁，主角固定填 "user"，其他人填名册里的名字，一条只属于一个人；text 一句话；topics 是 1–3 个主题词（饮食、作息…）；anchors 是原文里可供检索的关键词；有时效的在 until 写到期的故事内时间。先和「生活小档案」已有的条目查重。
- 用编号 d1、d2…：被正文推翻或纠正 → update；过了时效 → archive；记错了 → remove。

【记录冲突 conflicts】（很少用到）本楼正文和已有记录直接矛盾，正文没有交代变化的经过，也不能用时间跳跃或换了场景来解释时（同一场景里着装无故变了、已经用完的物品又出现、已退场的角色无交代地登场），对应的字段不更新，改为记一条：about 写矛盾的对象，record 写原记录的说法，text 照抄本楼正文的原句。最多 3 条。正文交代了变化，或只是多了新信息的，不算冲突，照常更新。{{knowledge_rule}}{{vars_rule}}
