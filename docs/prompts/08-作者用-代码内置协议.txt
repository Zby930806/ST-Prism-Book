【来源】只记该角色本楼亲耳听到、亲眼看到或被人告知的:主角当面说的、当着其面做的、第三人转告的。主角的内心独白、叙述旁白、该角色不在场时发生的事都不算,该角色并不知道。
【记认知,不记真相】把握程度写在句首:认定…/怀疑…/听说…/主角自称…。角色被骗就照记被骗后的认知(主角谎称是商人 → “认定主角是行商”),不注明真相;日后被揭穿,用 update 改写原条(如“得知主角其实是王子,此前一直被瞒”),不另加一条矛盾的。
【记什么】角色第一次得知的主角名字、身世、过往经历、秘密、私人喜好与习惯、主角自称或刻意隐瞒的身份。外貌、当场可见的举动和公开身份人人看得到,不必记;一次性的琐事不记。
【与信息差分工】信息差只记正文明确写出的隐瞒或缺席;这里记每个角色已经知道或以为的。主角刻意隐瞒的事,隐瞒本身仍按【信息差规则】记,这里只写该角色此刻的认知。
【查重】先对照材料中的「角色对主角的了解」列表,按“同一角色 + 同义内容”查重;已有的不重复 add,认知加深或改变用 update 改原条。
【add】who 写角色名册中的确切名字(含本楼 npcs.add 新登场或改名后的名字),不能是主角;名册里没有的角色不记。text 一句话只写一件事。
【update/remove】用列表编号 k1、k2… 指代:认知被纠正或加深 → update 写改写后的完整内容;记错了(该角色其实不知道,或记到了别人头上)→ remove。拿不准不动。
输出 knowledge 时 stateChanges 同时列出 "knowledge";本楼没有新得知就不输出该字段。

===== RECALL_BRIEFING_END（向量召回块的结束语）=====
〔相关回忆结束〕以上是按需取回的旧片段,按各自标注的时间理解;当前明确剧情优先,人物只知道自己经历或得知的事。不要复述,也不要模仿其中的记录句式。

===== LEDGER_PROTOCOL =====
【棱镜宝书旁注读取与正文分工】
历史消息尾部的 <bbs_items> / <bbs_vars>（含带属性或旧版无属性标签）是插件写回的结算旁注，不是角色台词或正文输出模板。读取其中的已结算变化，以理解物品和变量状态；快照已包含的变化不要再累加，历史记录不覆盖较新的状态。
你的任务是续写故事：新的获得、交付、消耗只在自然正文中描写，由摘要与插件负责记账。不要复制、续写或另造物品/变量变动清单，不输出上述旁注标签，也不要把旁注改写成正文中的账单。此分工不取消另行要求的时间标签或正常剧情中的盘点。

===== NPC_LOCATION_EVIDENCE_PROTOCOL =====
【NPC 定位证据】
- 本楼输出 npcs.add/update 的非空 location 时，同对象必须给 locationEvidence：从【本轮对话】连续照录能说明该角色本轮位置的短句，原文怎样称呼该角色就照原文，不必出现名册里的名字。不能引用旧名册、历史摘要、闪回或计划作为当前定位。
- 引文应原样复制；校验仅容忍排版空白、换行、成对 Markdown 行内强调标记，以及全角半角、引号样式和省略号写法的差异。文字、标点、语序与否定必须保留，不得拼接不同片段、改写或自行添加引号/省略号；英文单词间空格不能删成另一个词。引用不含程序附加的 [M…-P…] 编号或来源提示，不得跨消息拼接。
- 主角离开而定点角色未同行、此前打算留守、暂无新消息，都不构成重新确认旧位置；此时省略该角色 location/locationEvidence，由系统保留最后确认并标记过期。角色重逢或正文明确交代其远方现位置时才重新确认。
- 空 location 表示去向不明，不需引文；follow:true 表示同行，不同时写 location。只有定位操作才附 locationEvidence，同一角色每楼最多一次定位。证据仅用于解析校验，存储前移除，不进入正文或档案。
- 定位原话拿不准时只省略该角色的 location/locationEvidence，建档和其他字段照常输出；新登场的角色不能因为定位不确定就不建档。
