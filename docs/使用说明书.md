# 棱镜宝书使用说明书

适用版本：1.4.0

棱镜宝书（Prism Book）是 SillyTavern 的长期记忆扩展。它为每层 AI 回复写摘要，摘要积累后合并为多层总结；同时记录时间、地点、人物、物品、计划等剧情状态。生成正文时，较早的剧情以摘要代替原文发送，当前状态随之发送，长聊天因此能保持前后一致。

本扩展基于柏柏的 [ST-BaiBai-Book](https://github.com/baibai-git/ST-BaiBai-Book) 修改，数据与原版通用。原作信息和授权范围见 [NOTICE.md](../NOTICE.md)。

## 1. 功能一览

| 功能 | 作用 | 默认 |
|---|---|---|
| 摘要与总结 | 每层 AI 回复写一条摘要，积累后合并为总结和二次总结，代替移出窗口的旧正文 | 开启 |
| 状态记录 | 时间地点、主角、主要角色与 NPC、物品、场景、计划与悬念、信息差、角色对主角的了解（默认关闭）、自定义变量，各有页面，可手动修改 | 开启 |
| 时间标签 | 正文开头和结尾各写一个时间标签，故事时间由正文给出 | 随自动摘要开启 |
| 双子札记 | 模型在故事外就后续写法提出问题，确认后的方案成为「安排」，可注入正文 | 关闭 |
| 创作规划 | 生成分阶段的剧情规划，确认后只把当前阶段注入正文；可不填要求一键生成 | 没有规划时不注入 |
| 世界书 | 根据剧情生成世界书条目的建议，审核后写入，可撤销 | 手动生成 |
| 向量记忆 | 检索与当前剧情相关的旧片段并注入正文 | 关闭 |
| 楼层面板 | 在每条 AI 回复下方查看、编辑本楼的摘要和状态变动 | 关闭 |

## 2. 安装与更新

### 安装

1. 在酒馆扩展面板中点击「安装扩展」，填入 `https://github.com/Zby930806/ST-Prism-Book`。
2. 安装完成后刷新页面。

最低支持的酒馆版本为 1.12.13，未在所有酒馆版本上实测。

手动安装：把完整的 ST-Prism-Book 文件夹放进酒馆用户目录下的 extensions 文件夹，确认第一层有 manifest.json，且有 dist/index.js 和 dist/index.css。

### 更新

在酒馆的「管理扩展」中更新，更新后刷新页面。打开酒馆扩展面板中的「在扩展更新时通知」后，有新版本时酒馆每天提示一次；酒馆自身升级时，也会按酒馆的设置顺带更新本扩展。插件自己不检查更新，也不会装上原版柏宝书的更新。

升级不需要全部重新摘要：原有的摘要、L1/L2 总结和状态继续使用，无法识别的格式进入只读保护，不覆盖原数据。从较早楼层开出的分支或检查点里，复制过来的、包含分支点之后楼层的总结会自动删除并提示，原聊天不受影响。

### 从柏宝书迁移

1. 备份酒馆数据、设置和旧插件目录。
2. 停用柏宝书，并把它的文件夹移出 extensions 目录（只改名无效）。两个版本共用同一份数据，不能同时启用。
3. 安装本扩展，强制刷新页面。
4. 打开旧聊天的摘要页，检查兼容状态。先在聊天副本上试用，确认无误再用于正式聊天。

详见 [旧记忆接续说明](LEGACY-COMPATIBILITY.md)。

### 打开宝书窗口

- 输入框旁魔杖菜单（扩展菜单）中的「棱镜宝书」，始终可用。
- 「设置 → 基本设置」中可打开酒馆顶栏按钮和聊天框上方的按钮；「屏幕悬浮球」可在屏幕上放一个可拖动的入口。
- 窗口导航依次为摘要、物品、场景、角色、变量、札记、世界书、设置。
- 手机返回键、电脑浏览器的后退键和 iOS 侧滑返回，先关闭最上面一层（菜单、弹窗、规划讨论等），最后关闭宝书窗口。

## 3. 第一次使用

### 3.1 确认已启用

设置页顶部的总开关显示「棱镜宝书已启用」即可（默认开启）。关闭后不再摘要、总结和注入，也不再隐藏新的楼层，已有记忆保留。已由棱镜宝书隐藏的旧楼层仍保持隐藏，正文模型看不到它们的原文和摘要；当前聊天有这类楼层时，设置页顶部提供「恢复显示这些楼层」（只恢复棱镜宝书隐藏的楼层）。

「设置 → 高级过滤 → 排除角色」中的角色不启用记忆。排除名单只对单角色聊天生效。加入名单前已隐藏的旧楼层同样保持隐藏，打开这个角色的聊天后可在设置页顶部恢复显示。

### 3.2 设置副 API（推荐）

摘要和总结默认使用酒馆当前连接的主 API（请求不带聊天记录）。跟随主 API 时，请求期间把主 API 的最大回复临时设为「设置 → 摘要设置 → 跟随主 API 时的最大回复」（默认 32000），不能超过模型的单次输出上限；首次失败时自动改用 8192 重试一次。建议另设一条渠道，避免占用正文的生成队列和额度：

1. 打开「设置 → 副 API」，点击「添加渠道」。
2. 填写渠道名、API 地址（OpenAI 兼容接口，如 `https://api.example.com/v1`）、API 密钥和模型。可点击「拉取模型列表」从列表中选择。
3. 按需调整温度、最大输出、超时和思考强度。最大输出包含思考过程，摘要经常被截断时调大，但不能超过模型的单次输出上限。超时在开启流式传输时按多久没有收到新内容计算；思考型模型或批量补摘可调到 300–600 秒。
4. 接口接受末尾的 assistant 消息时（如 Claude），可打开「发送预填充」，减少格式错误；不确定时保持关闭，很多 OpenAI 兼容接口会因此报错。开启后回复开头常出现与核查无关的文字或回复空内容的，也应关闭。
5. 点击「测试渠道」确认连通，再点击「完成」保存。点 × 或弹窗外关闭会放弃修改。
6. 在「摘要使用」「总结使用」中选择这条渠道。二次总结使用总结的渠道，批量补摘使用摘要的渠道。

可以添加多条渠道，摘要和总结分别指派。渠道与柏宝绘等同源插件共用。

### 3.3 开始聊天

正常聊天即可。每次发送新消息时，插件为上一条 AI 回复写摘要，结果显示在「摘要」页。失败时，原因、处理方法和设置位置显示在摘要页概览下方。

希望回复一结束就写摘要时，打开「设置 → 摘要设置 → 回复结束后立即摘要」。之后重抽或翻页生成新回复，已写的摘要作废、新回复结束后重写，会多用请求；续写或编辑这条回复后，摘要按新内容重写。

### 3.4 已有的长聊天

插件不会自动为整个旧聊天补摘。

- 在摘要页点击「补摘」批量补摘。待补摘达到 30 层时，可选「较早楼层合并摘要」：最近 20 层逐层摘要，更早的楼层每 10 层合并一次请求，只写每层的摘要和起止时间，不记录状态，请求次数少得多。确认框中显示请求次数，两个数字可以修改。合并的一组没写全时先保存写好的楼层，其余拆小重试；逐层摘要的楼层每层写完按设置合并为总结，全部完成后把能合并的都合并完。
- 自动摘要每次只补最早的一个缺口。前面缺摘要的楼层多于一层时，发送消息会被拦截，聊天末尾出现「本次生成已拦截」提示；补齐后关闭宝书窗口，提示会自动删除。只有状态栏、时间标签或思考内容、没有正文的楼层无法摘要，在「未摘要楼层」中点「标为番外」跳过。
- 旧聊天没有故事时间时，可在摘要页底部设定「当前故事时间」，之后的时间由此推算。
- 已有摘要、需要按当前提示词从头重做时，用摘要页的「全部重新摘要…」，见第 5 节。

### 3.5 其他功能的 API（按需）

- 双子札记：札记页底部的「独立 API 设置」。
- 创作规划和世界书：默认使用札记的 API（不需要启用札记），也可各自单独设置。
- 向量记忆：「设置 → 向量记忆」。
- 「设置 → 札记与规划 API」卡片显示这三项是否已设置及所用模型，按钮可跳到对应的设置位置。

## 4. 记忆的工作方式

### 4.1 摘要、总结与二次总结

- 摘要（L0）：每层 AI 回复一条，包括正文摘要、起止时间和本楼的状态变动。每条摘要默认不超过 300 字（「设置 → 摘要设置 → 摘要字数」）。
- 总结（L1）：摘要积累到 12 条时合并为一条总结，最近 3 条摘要保留不合并。总结的篇幅以字数档位为基准（详细 300–500 字、精简 150–300 字），「摘要字数」高于 300 时两档都按比例放大，最多 3 倍；「字数档位」的说明中显示当前的总结字数。
- 二次总结（L2 及以上）：总结积累到 6 条时合并为 L2；L2 及以上每 3 条再合并一层。

以上数量在「设置 → 摘要设置」中修改。摘要页的「多选」可手动合并相邻的条目，「立即总结」按阈值检查一次。被合并的摘要不删除，只是不再单独显示和注入。总结因回复被截断、超出上下文等原因失败后，同一批摘要不再自动重发，摘要页显示「总结已暂停自动重试」；修改总结所用的渠道、模型或最大输出后照常进行，也可点「重试总结」。

### 4.2 发给正文模型的内容

- 最近 3 条 AI 回复及其间的用户消息照常全文发送（「设置 → 摘要设置 → 保留最近 AI 消息数」）。更早、已摘要的楼层由酒馆隐藏，不再发送；原文仍在聊天中，可以翻看。
- 插件注入的内容：历史摘要（带「三天前」这类相对时间）、当前状态（眼下局势、主角、人物、物品、场景、计划与悬念等）、时间标签指令；启用时还有召回的旧片段、已确认的札记安排和创作规划的当前阶段。
- 注入总量默认不限制。需要控制时，在「设置 → 注入设置 → 记忆注入预算」填写数值（按 tokens 估算）。填写后先预留时间标签指令和只读账本说明，其余按历史 45%、状态 40%、召回 15% 分配；不召回时召回的份额给历史。历史放不下时保留故事开头的总结和最近的摘要，并注明缺了哪段时间。各项状态可在注入设置中单独关闭，关闭后摘要照常记录。
- 对话较短时，token 用量与不装插件时相近；旧楼层被隐藏后才开始节省。在摘要页「摘要与总结」旁点击「估算注入量」，可分项查看插件注入大约占多少：历史摘要、当前状态等，以及召回（按上一次召回的内容）、札记安排、创作规划和连续性提醒，最后一行为合计。

### 4.3 故事时间

- 启用自动摘要时，插件要求正文在开头写 `<bbs_start>时间</bbs_start>`、结尾写 `<bbs_end>时间</bbs_end>`。这两个标签在聊天中自动隐藏。
- 新聊天从正文写明的时间开始；没有时从「故事第1天 08:00」开始。尚无摘要时，可在摘要页底部设定开场时间。见 [开场时间](开场时间.md)。
- 注入的历史摘要按当前故事时间换算出「三天前」等相对时间，人物年龄也随时间推算。

### 4.4 状态随剧情回退

状态不单独保存，每次由各楼摘要中的变动按楼层顺序计算得出。重抽、删除楼层或重新摘要后，物品、人物、变量等随之变化，始终与当前剧情一致。页面上的手动修改单独记在摘要上，计算时排在模型结果之后，重新摘要后仍然保留；那一楼的回复被翻页、重新生成或标为番外时，移到之前最近一条有效摘要上。

### 4.5 番外楼

启用楼层面板后，点击卡片头部的星光图标键，可把这一楼标为番外：不摘要、不总结、不隐藏、不注入，也不计入时间线，适合小剧场。再点一次取消。

## 5. 各页面

### 摘要

- 概览：摘要、总结和待补摘的数量，以及「补摘」和「全部重新摘要…」按钮。全部重新摘要没有完成时，概览下方显示已完成的层数、停下的楼层和「继续」「结束」。
- 楼层光谱：每层 AI 回复一格，按原文、逐楼摘要、已并入总结、已并入二次总结区分深浅，待补摘为条纹，番外为斜线；悬停显示楼层范围。
- 未摘要楼层：连续的待补摘楼层合为一段。单层点击直接补摘，多层的一段打开批量补摘，只补这一段。没有正文的楼层单独列出，可点「标为番外」跳过。
- 当前局势与计划：局势卡、计划和悬念。编辑未了结计划、悬念的内容和期限时，修改单独保存，重新摘要来源楼层后仍然生效；删除计划或悬念前先确认。
- 创作规划：见第 7 节。
- 摘要与总结：可搜索；点开条目可修改文字和起止时间。「多选」后可合并总结或删除所选，「立即总结」按阈值检查一次。
- 全部重新摘要：按楼层顺序重新请求模型，替换摘要和模型记录的状态，可以从指定楼层开始，之前的楼层保留现有摘要。在各页面新增、修改、删除的物品、角色、地点等单独保存，完成后仍然保留，从 Horae 迁移来的状态按正文重新推算；直接改写过的摘要正文，以及已了结计划悬念的文字和各条目的记录时间，会被新结果替换。确认框写明请求次数。取消、失败或刷新页面后可以从停下的楼层继续。只在需要从头重做时使用，使用前先备份。
- 页面底部：开场时间（旧聊天显示为「当前故事时间」）、导入旧总结、旧记忆兼容。

### 物品

列出随身和寄存在别处的物品及数量。摘要时按正文增减，也可手动添加、修改、删除；页面上的修改单独保存，重新摘要或全部重新摘要后仍然保留。正文中的 `<bbs_items>` 是物品变动旁注，在聊天中隐藏。

### 场景

地点按层级记录（如城市、街道、旅馆）。主角到过的有名地点都会记录，写不出稳定特征的只记地点、不写描述。「有名」指专有名称：「酒馆」「路边」这类泛称和只被提起、约好以后去的地方不记录，主角在泛称的地方时位置取能确认的上级。注入时，当前地点及各级上级地点带描述，其他已知地点只列名称（完整路径）。页面上可以手动添加、编辑或删除地点，描述可以留空；编辑时清空描述后保存即删除原描述。

### 角色

- 分为主角、主要角色、NPC 三块。主角只记 {{user}} 本人；除主角外的主要登场人物记为主要角色；其余登场的人记为 NPC。
- 没有名字的 NPC 记为「职业 + 字母」（如「酒保A」）。报出真名后改名接续，原有记录保留，卡片显示「原记为」。
- 档案缺外貌、身份或性别时，卡片底部有「从原文补全」：检索全部楼层中提到该角色的原文，用摘要的 API 请求一次，确认后只补空字段。摘要时也会自动补，可在「设置 → 摘要设置 → 回看原文补全角色档案」关闭。
- 页面顶部的「角色重新建档…」按原文补齐名册里漏记的角色，并重新整理全部角色的身份、性别、年龄、外貌和性格，位置、着装、伤情、好感和关系不改动。确认框写明两步各约多少次请求；完成后列出新角色和档案改动，勾选后才写入，写入的内容重新摘要后仍然保留。可以随时取消，之后继续、先审核已找到的结果或放弃。请求次数较多，使用前先导出聊天备份。
- 角色卡显示着装、伤情、所在位置和五档好感估计。角色卡自带好感系统时，可在「设置 → 注入设置 → 角色好感估计」中关闭好感的注入。
- 「信息差」（默认收起）记录谁知道、谁不知道某件事，可结案、重开或删除。注入时只提醒在场且不知情的角色，每次最多 12 条，不知情者有在场角色的优先，超出时注明另有几条未列出。
- 开启「设置 → 注入设置 → 角色对主角的了解」后，主要角色和 NPC 的角色卡最下方显示「对〔主角名〕的了解」（默认收起）：该角色知道或以为的主角的事，被骗时记的是被骗后的认知。可添加、修改和删除，已有同一句时不重复添加。作为主要角色或在场时随正文发送，每人最多 15 条；没有记下的主角私事按该角色不知道处理。
- 主角换了场景或故事时间过了一天后（「故事第N天」、带年月日的中文日期等写法都能判断），没有同行的角色位置记为「未确认」。主角回到某个角色最后确认的地点或附近时，发给正文模型的内容标为「最后确认在此处」，并说明按身份、作息和经过的时间判断是否还在。
- 注入设置中关闭了某项（如主角信息、NPC 名册、场景信息、生活档案、信息差）时，对应区块显示「注入设置中已关闭，不发送给正文模型」。「角色对主角的了解」关闭后不再记录，已有条目照常显示，并注明「注入设置中已关闭：不再记录，也不发送给正文模型」。

### 变量

自定义的 JSON 状态，用于血量、好感度数值、金钱、任务进度、剧情标记等内置记录没有覆盖的内容。

- 模板分全局、角色、聊天三层，合并为初始值；变量的值按聊天独立，随剧情回退。
- 「含义」同时发给正文模型和摘要模型，「规则」只发给摘要模型，说明何时、如何修改。
- 正文中的 `<bbs_vars>` 是变量变动旁注，在聊天中隐藏。

写法和示例见 [FAQ 第 5 节](../FAQ.md#5-自定义变量专题)。

## 6. 双子札记

模型在故事外，就后续写法提出最多四个问题（Q1–Q4），每题附一个暂定写法。确认后的方案成为「安排」，可以注入正文。

1. 打开「札记」页，在底部「独立 API 设置」中填写 API 地址、密钥和模型名，点击「保存」。札记只使用这里的 API。
2. 打开页面顶部的「启用双子札记」。正文生成完成后，在札记页或聊天中最新回复下方的札记卡片里点击「生成札记」。
3. 每题下方的「采用方案」可以修改。点击「确认安排」后进入「已确认的安排」，不采用则点「搁置」。
4. 需要正文按安排书写时，在底部「自动生成与注入」中打开「注入已确认安排」。待兑现和进行中的安排注入正文，标为已完成或已取消后停止注入；「已确认的安排」标题旁显示实际注入的条数。填写了记忆注入预算时，安排清单最多 16000 字，放不下的条数会显示出来。

- 「自动生成札记」打开后，每次正文生成完成自动生成一份。模型回复「本轮无需新增札记」时不保存札记，只在状态中说明。
- 札记卡片显示在聊天中，不需要启用楼层面板；可在「自动生成与注入」中关闭「在聊天中显示札记」。
- 札记与所在楼层的正文绑定，该楼被改写、重抽或删除后札记失效，只能查看；更早楼层的改写、改名和隐藏不算改动。已确认的安排不随札记失效，照常注入，并标出「依据的正文已改动」，不再适用时可一键取消。
- 札记页和札记卡片都可以删除札记，由这份札记确认的安排一起删除。
- 札记页底部可查看原版提示词和实际使用的整理版。

详见 [双子札记说明](双子札记.md)。

## 7. 创作规划

位置：摘要 → 创作规划。规划是写作方向，不是已发生的事；确认后每次只把当前阶段注入正文，正文仍以已有剧情和用户最新的要求为准，不会替用户的角色做决定。

### 生成规划

- 一键生成：没有规划和草稿时，「创作规划」中显示「一键生成规划」卡片，点击「一键生成」即可。模型根据角色卡、世界书、宝书记忆和最近剧情规划后续 3～6 个阶段。已有规划或草稿时，在「修改或重新生成规划」中点击「一键生成」，确认后生成。
- 按要求生成：展开「生成规划草稿」，写下希望的走向（人物关系、转折、节奏、不想出现的情节），选择阶段数（1–12），点击「生成规划草稿」。
- 两种方式和规划讨论都会参考：最近 8 层正文和用户原话、已有的逐楼摘要和总结、当前状态（紧凑文字，未了结的计划和悬念在最前）、角色卡、当前启用的世界书条目，以及双子札记中已确认的安排。记忆注入预算为 0（默认）时摘要、状态和安排不限字数。

### 确认与使用

1. 生成结果先存为草稿。在草稿中修改标题、整体方向、约束和各阶段的目标、剧情要点、发展方式、推进条件，点击「保存草稿」。模型的回复有多余字段、超长文字或阶段数不符时，自动调整后照常存为草稿，调整列在草稿上方。
2. 点击「确认加入计划」后生效，从第一阶段开始。确认前不影响正文；重新生成只替换草稿，不替换正在使用的规划。确认时逐个阶段检查注入长度，有阶段超出 16000 字时不加入，并指出第几阶段多出多少字。
3. 阶段可手动切换（「下一阶段」「结束规划」），也可随时暂停。规划卡片中的「推进节奏」决定每轮回复推进多少剧情要点：慢（每轮最多一个，也可以不推进）、适中（默认，每轮最多一到两个）、快（可以多个，但不在一轮写完整个阶段），修改后从下一次生成起生效。改写、重抽或删除规划参考过的正文后，规划暂停并弹出一次提示，「创作规划」折叠行显示「剧情有改动，已暂停」，核对后点击「核对后重新启用」。

### 推进条件检查

- 「检查推进条件」把当前阶段和本阶段上次检查以来的正文（至少最近 max(6, 间隔×2) 条，放不下的较早楼层改用逐楼摘要）发给规划 API，判断推进条件是否已在正文中满足；计划、约定和猜测不算满足。手动检查的结果只作提示；自动检查失败或因规划 API 没填好没有运行时，规划卡片中留一条说明。
- 可打开「每 N 个 AI 楼自动检查」，以及「满足时自动切换阶段」。自动切换后，卡片中显示切换的楼层和依据，可点「退回第 N 阶段」撤回；最后一个阶段不会自动结束。
- 已确认的规划中，推进条件旁有编辑键，可以直接修改。

### 规划讨论

「规划讨论」默认由对话角色 Qiheng 回答（可在讨论窗口「更多操作 → 讨论角色」换成自定义角色，填写名字、人设提示词，可上传头像；讨论的规则照常生效），用于讨论人物动机、节奏或走向。她说话口语化、短句连发，会吐槽也会热烈地夸人，偶尔说粗话，对说话客气的人和严肃的话题会收敛；打招呼、道谢或说累时只回一两句，不顺势展开规划；只依据提供的资料回答，不替用户拍板。记录按聊天保存，发送时同样带上世界书条目和札记中已确认的安排。讨论不修改规划；需要采纳时点「生成草稿」，按讨论生成新草稿，同样需要确认后才生效。讨论最多保留 12 轮、48000 字，满了可删除最早的一轮或清空。

### 使用的 API

默认使用札记中填写的 API（不需要启用札记），也可在「规划 API 设置」中单独设置（最大输出默认 8000）。生成、讨论和手动检查只在点击按钮时请求，打开自动检查后按间隔请求。

详见 [创作规划说明](大纲规划.md)。

## 8. 世界书

根据剧情生成世界书条目的建议，审核后写入所选的世界书。所有写入都需要确认，写入的改动可以撤销。

1. 打开「世界书」页，在「写入目标」中选择世界书。默认使用聊天绑定的世界书，没有时使用角色主世界书；也可点「新建并绑定到当前聊天」，新建一本只在这个聊天中启用的世界书。
2. 在页面底部选择使用的 API（默认使用札记的 API）和修改权限。
3. 点击「生成建议」。模型读取上次处理之后的新楼层，建议列在「待审核的建议」中。
4. 逐条「应用」「编辑后应用」或「忽略」，也可整批处理。修改类建议显示改前改后对比，并注明依据的楼层。
5. 写入的改动记在「已写入记录」中，可以撤销。

- 修改权限分三档：只新增（默认，只新建条目）、可补充（追加内容、加关键词）、可修改（替换、改写）。超出权限的建议由程序拦截。
- 写进角色主世界书的条目在这个角色的所有聊天中生效。
- 自动建议默认关闭；打开后每隔若干个新的 AI 楼层生成一次，同样需要确认后才写入。
- 建议依据的楼层被改写、重抽或删除后，这批建议标为失效，可核对后「仍然应用」，或「从第 N 楼重新读取」后重新生成。

详见 [世界书说明](世界书.md)。

## 9. 向量记忆

摘要会压缩掉细节。向量记忆为每条摘要建立索引，并保存这一段的原文（含主角的发言），生成时按当前剧情检索最相关的旧片段，以原文或摘要的形式注入，适合找回早期的伏笔和细节。

- 在「设置 → 向量记忆」中启用，填写 Embedding 的地址、密钥和模型（必须是 embedding 模型）。查询重写需要对话模型，地址和密钥可沿用 Embedding。重排模型已预填，服务商不支持重排时请清空模型；不重排时只发送摘要，不发送原文。
- 装有服务端插件「柏宝库」时可跨聊天、跨设备召回；没有时使用浏览器本地索引，只召回当前聊天。
- AI 楼数少于「开始召回的 AI 楼数」（默认 30 层），或所有楼层都还在保留窗口内时，不召回。
- 填写了记忆注入预算时，召回内容占扣除时间指令和账本说明后剩余部分的 15%，原文放不下时改发这一段的摘要。预算默认不限制。
- 召回在正文生成前进行，等待期间可以点酒馆的停止键取消。已有的摘要会在召回前自动补入索引；换了 Embedding 模型后，在「设置 → 向量记忆 → 索引维护」点「清空并重建」。
- 「设置 → 记忆与召回 → 召回调试」分五步显示上次召回的检索词、候选、得分和注入结果，并写明没有注入的原因，用于排查不召回的原因；横幅下方列出每一步的用时。
- 补建索引和查询重写同时进行；查询重写的请求 12 秒没返回时会再发一次，先返回的算数。重写附带的上下文超过「附带上下文上限」（默认 16000 字）时先精简。

详见 [FAQ 第 6 节](../FAQ.md#6-向量记忆答疑)。

## 10. 楼层面板与召回按钮

### 楼层面板

在「设置 → 基本设置」中打开「启用楼层面板」后，每条 AI 回复下方显示本楼的摘要卡片：

- 查看、编辑本楼的摘要和状态变动。
- 重新摘要：新结果与现有摘要并排对比，选择「用新的」才替换。
- 标为番外：卡片头部的星光图标键。
- 不一致：本楼正文与已有记录矛盾、又没有交代变化时，标出两边的原文，可选择提醒正文模型或忽略。
- 召回记录：启用向量记忆时，记录生成这一楼之前召回了什么。

### 召回按钮

启用向量记忆后，输入框上方的快捷回复栏显示「召回」按钮和上次召回的段数。点击可查看召回的旧剧情、注入的是原文还是摘要；没有召回时显示原因。可在「设置 → 基本设置 → 在快捷回复栏显示召回」中关闭。

装了 QR助手时，快捷回复栏的按钮会收进它的菜单：「召回」和「棱镜宝书」按钮在菜单的「棱镜宝书」一组中，点击与原按钮相同。想让它们留在输入框上方，在 QR助手的白名单中加入。

## 12. 数据、备份与隐私

### 数据存在哪里

- 每层的摘要和状态变动：存于该条消息，随聊天文件保存。
- 总结、创作规划、札记、世界书的读取进度和写入记录：存于聊天元数据，随聊天保存。
- 设置：存于酒馆的扩展设置（服务器上的 settings.json），跨设备同步。
- 浏览器本地：上次打开的页面、悬浮球位置、折叠状态、召回缓存，以及未装柏宝库时的本地向量索引。

### 备份

- 聊天：用酒馆的聊天导出，摘要随聊天文件一起保存。
- 设置：「设置 → 数据与迁移 → 设置备份」导出设置，文件不含 API 密钥。导入前列出会修改的内容，确认后才导入；地址与本机是同一个服务器的保留本机已填写的密钥，地址换了服务器的不保留、需要重新填写（确认框写明地址的变化），API 渠道和排除名单只增加、不删除。
- 变量方案：在变量页导出模板和说明（不含值）。

### 带数据创建新对话

把当前聊天最近的全文、合并后的历史摘要和当前状态带入新对话，适合续写前传、分出支线。启用向量记忆且装有柏宝库时，另存旧聊天的向量快照，供新对话召回。保留窗口之前还有没摘要的楼层时，卡片上会提示，这些楼层的剧情不会带入，可先补摘。角色的曾用名一并带入。

### 从 Horae 迁移

「设置 → 数据与迁移 → 从旧版 Horae 迁移」把当前聊天里 Horae 的逐楼摘要、自动总结、物品和计划转为棱镜宝书的数据。每个聊天分别执行；当前聊天已有棱镜宝书数据时会被覆盖，Horae 的原数据不变。迁移来的物品、计划等状态单独保存，重新生成那一楼的摘要时保留。没有 Horae 记录的楼层迁移后需要补摘，预览和完成提示中写明层数。

### 隐私

- API 密钥保存在酒馆的扩展设置中。分享 settings.json 或设置截图前，先删除或遮盖密钥；「设置备份」导出的文件不含密钥。
- 报错的「技术细节」中，密钥和带参数的地址会被遮盖。

## 13. 常见问题

| 情况 | 处理 |
|---|---|
| 完全不生效 | 检查总开关；角色是否在排除名单中；没有指派副 API 时，酒馆主 API 是否已连接 |
| 摘要失败 | 摘要页概览下方显示原因和设置位置；常见原因是渠道不通、密钥无效或模型输出格式不对。接口支持时可打开「发送预填充」（开启后回复开头出现无关文字或空内容的应关闭），或更换模型、调高失败重试次数 |
| 摘要报「主 API 请求失败」 | 没有指派副 API 时，插件把主 API 的最大回复临时设为「设置 → 摘要设置 → 跟随主 API 时的最大回复」（默认 32000），超过模型的单次输出上限时会被拒绝，首次失败自动改用 8192 重试。仍失败时调小这项设置，或给摘要指派副 API 渠道 |
| 回复被截断 | 调大对应位置的「最大输出」：摘要和总结在「设置 → 副 API → 对应渠道」（跟随主 API 时为「设置 → 摘要设置 → 跟随主 API 时的最大回复」），札记在札记页「独立 API 设置」，创作规划在札记的 API 或「规划 API 设置」。思考过程也计入最大输出 |
| 聊天里出现「本次生成已拦截」 | 前面有楼层缺摘要。按提示补摘，补齐后关闭宝书窗口即自动删除；提示后面已有新消息时请手动删除。这条提示不会发给正文模型，插件停用后同样如此 |
| 旧楼层被隐藏了 | 正常现象：已摘要且超出保留窗口的楼层不再发送，原文仍在聊天中。停用插件或排除角色后，已隐藏的旧楼层仍保持隐藏；可在设置页顶部「恢复显示这些楼层」 |
| 正文露出 `<bbs_start>` 等标签 | 时间标签需要在同一行内闭合才能隐藏。可在自定义时间标签提示词中强调「每个标签闭合在同一行」 |
| 正文没有时间标签 | 模型没有遵循时间标签指令，可换用更简单的自定义提示词或更换模型 |
| 提示「……项更新没有写入，原记录保持不变」 | 最后一次尝试中这几项更新仍不符合要求（括号里写明原因），只去掉了这几项，摘要和其他状态已保存；楼层面板「没写入的内容」中也会列出。需要时手动修改，或在楼层面板重新生成本楼摘要。见 [摘要证据校验说明](摘要证据校验说明.md) |
| 摘要页显示「总结已暂停自动重试」 | 合并总结时回复被截断、超出上下文、参数被拒绝或被内容审核拦截。调大总结所用的最大输出、换模型或渠道后照常自动总结，也可点「重试总结」 |
| 有楼层一直待摘要，提示「清洗后没有故事正文」 | 编辑这一楼的正文，或在「未摘要楼层」中点「标为番外」，或删除这一楼 |
| 摘要页显示「全部重新摘要未完成」 | 上次的全部重新摘要被取消、失败或刷新页面打断。点「继续」只处理还没有重新摘要的楼层；不再需要时点「结束」，已有摘要不变 |
| 用了插件 token 还是很多 | 先点「估算注入量」，看「合计」：插件注入占比小时，主要来自预设、世界书或窗口内正文；占比大时，调小摘要字数、减少召回或状态 |
| 向量记忆不召回 | 看「召回调试」：常见原因是查询重写的模型为空或不是对话模型、楼层不足设置的门槛（默认 30 层）、得分没有达到阈值、填写的注入预算过小、换了 Embedding 模型没有清空并重建 |
| 召回很慢，正文迟迟不开始 | 召回在正文生成前进行，可以点酒馆的停止键取消。看「召回调试」横幅下方每一步的用时：查询重写慢时换一个不思考、负载轻的对话模型，或调小「附带上下文上限」；重排慢时调小「重排候选数」。经常等很久时也检查各端点的地址、网络和超时 |
| 角色受伤后每轮都写伤 | 伤情只在动作牵涉伤处、影响行动或被人提及时才要求写出；记录满一天未更新时，「伤势进展提醒」会让正文写出好转等进展（故事时间不明时按楼层数判断，只发一级中性提醒，不加重），可在注入设置中关闭 |
| 摘要里写到的角色，角色页里没有 | 升级前漏记的角色不会自动补上：在角色页点「角色重新建档…」按原文补齐，或在楼层面板重新生成那几楼的摘要 |

更多问题见 [FAQ](../FAQ.md)，报错的含义和处理见 [常见报错](常见报错.md)。
